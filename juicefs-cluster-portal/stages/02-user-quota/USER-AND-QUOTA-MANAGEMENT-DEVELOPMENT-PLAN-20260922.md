# 第二阶段总开发计划：用户管理与配额管理

> 日期：2026-09-22。状态：路线A及新建身份服务产品已确定为389 Directory Server（389 DS），待S2-0核对实施参数；尚未部署。
> 本阶段采用路线A：LDAP统一业务用户，各客户端使用一致的UID/GID；不修改JuiceFS源码实现用户映射。路线B/C保留为历史备选。
> JuiceFS交付版本已批准为带B-catchup补丁的v1.4.1；本阶段不重新选型或复测版本性能。实际部署仍按既有制品要求核对二进制校验值。
> 本文统一开发范围、依赖、工作量与验收安排。LDAP配置及CA/证书流程见[路线A实施说明](features/juicefs-user-quota-management/JUICEFS-LDAP-USER-MANAGEMENT-IMPLEMENTATION-NOTES-20260922.md#34-ldap-ca证书和连接流程)；配额接口和数据模型复用现有专题计划，不重复编写。

## 一、交付目标

**在已完成的只读Portal上增加业务用户身份与目录登记、管理员目录配额管理，并用一台获准客户端验证LDAP身份、目录权限和配额及后端凭据保护；业务读写仍走原有存储路径。多客户端一致性留到第三阶段新环境联合验收，普通用户在Portal自助查看个人额度和目录明细留待后续增量。**

**新建身份服务选用389 DS，正式部署在两个不同服务节点。** 当前三节点存储集群允许单节点故障，LDAP也须在任一部署节点故障后继续提供在线身份查询和认证；具体节点、OS/版本、资源、复制及证书配置在S2-0核对。两节点是服务端身份高可用要求，与本阶段只用一台业务客户端做功能验证不矛盾。单实例只可用于隔离的早期功能开发，不算正式部署或高可用验收；不能用客户端身份缓存代替故障后的在线认证。[选型依据](features/juicefs-user-quota-management/LDAP-PRODUCT-SELECTION-RESEARCH-20260923.md)。

本阶段交付后，一个新用户的完整使用过程为：

1. 运维通过389 DS的受控管理入口创建业务账号、设置组关系；客户端通过SSSD/NSS/PAM使用该账号，不逐台创建同名本地账号。
2. 运维通过独立管理挂载准备用户目录；新目录创建即为`root:root`、0700，暂不交付业务用户。
3. Portal ADMIN在“存储用户”页通过可搜索下拉框浏览已有LDAP用户，选择并核对UID/GID后登记身份；再登记该用户目录，按需要设置容量和inode限额。本期不绑定普通用户的Portal查看账号。
4. 需要初始配额的目录先完成配额回读确认；随后由运维将新目录交付给指定LDAP用户。本期在一台获准客户端验证私有目录与共享模型目录的权限；跨客户端访问在第三阶段验证。
5. Portal ADMIN查看受管目录的额度、用量及变更记录；业务用户无需Portal账号即可正常使用文件系统。

目录登记与配额设置独立：可以登记而不限额；真正的文件权限由JuiceFS的POSIX权限/ACL决定，不由Portal管理记录代替。

## 三、组件分工与数据存放

| 组件 | 本阶段职责 |
|---|---|
| 双节点389 DS及客户端SSSD/NSS/PAM | 两个不同服务节点复制同一套业务身份、UID/GID和组关系；客户端配置两个可用端点或经验证的服务发现，完成身份解析、登录认证及故障切换；LDAP连接的TLS与PD/TiKV mTLS分别配置 |
| Portal，Linux账号`jfsweb` | 校验ADMIN/USER会话，提供页面和API；只读目录统计，经本机Unix Socket调用配额控制服务，不持有TiKV/Ceph凭据 |
| `quota-controller`，Linux账号`jfsquota` | 查询LDAP身份，管理目录记录，调用JuiceFS原生元数据接口查询/设置配额，持久化任务并回读确认；无需Ceph keyring或文件系统挂载 |
| 统计挂载和collector，Linux账号`jfsstats` | 保留第一阶段统计能力与服务账号分工，不新增个人目录三级统计；不承担目录交付或配额设置 |
| 独立受控管理挂载 | 供可信运维创建一级目录、设置owner和权限、应急修复；不启用业务挂载的`root-squash` |
| 业务JuiceFS挂载 | 使用统一UID/GID执行业务IO，按原生配额限制超额写入；基线启用`root-squash` |

Portal及控制服务拟继续部署在152；389 DS的两个部署节点、OS/版本及资源预算在S2-0核对，不默认占用现有150～152或改变其业务服务。不在157新增常驻管理服务；Prometheus/Grafana不随本功能重新建设。

与本功能相关的数据分为：

- **LDAP目录：** 业务账号与组的权威来源。Portal登记的是引用和核验结果，不另建UID/GID分配器，也不复制业务密码。
- **已有目录统计SQLite：** collector写入目录用量，Web在文件权限和连接方式上均只读。
- **新增存储管理SQLite：** 只由`jfsquota`读写，保存LDAP引用、受管目录、配额观测、任务及审计；本期不建立个人目录查看授权表。Web经Socket查询，不再增加配额展示数据库副本。Portal账号配置和会话签名密钥单独受保护；备份及恢复时核对管理员账号身份和审计归属，不能只恢复管理库就直接开放管理写入。
- **JuiceFS元数据所在的TiKV：** 保存真实文件权限、配额规则与计数。管理库记录流程和观测，不代替TiKV执行配额。

每个受管目录在管理库中有一个内部记录ID（resource ID），用于关联变更任务和审计；它不是UID、inode或访问凭据。详细表结构与API沿用[配额开发计划第五节](features/juicefs-user-quota-management/JUICEFS-QUOTA-MANAGEMENT-DEVELOPMENT-PLAN-20260922.md#五实现工作清单)。

过期数据按[方案11.8.5](features/juicefs-user-quota-management/USER-AND-QUOTA-MANAGEMENT-RESEARCH-20260914.md#1185-过期数据清理空间与备份)及[配额计划5.2.1](features/juicefs-user-quota-management/JUICEFS-QUOTA-MANAGEMENT-DEVELOPMENT-PLAN-20260922.md#521-过期记录清理与备份实施要求)实施：未确认预览24小时失效；终态详情180天、审计摘要730天；未决任务保留并受数量上限约束；最新配额观测覆盖更新。控制器每天小批量清理，备份按7天/7份/8 GiB轮换并保护最后有效副本。任务与审计共用操作表，首版不建设额外归档服务。

预览生成操作编号，正式提交只能确认已有编号；过期或已清理编号不补建，防止清理后旧请求再次执行。恢复备份须作废旧预览、核对未决操作和管理员账号身份。上述工作纳入原S2-2开发、S2-4验收，S2-0核对部署容量和保留参数，不另起实施阶段；当前工时仍为粗估，核对后按实际修订。

## 四、必须落实的权限边界

1. **区分三类身份。** LDAP业务身份决定文件访问；Portal ADMIN/USER决定网页功能；`jfsweb/jfsquota/jfsstats`是运行服务的Linux账号。三者不按同名自动互相授权。
2. **可信root与普通用户分开。** 获准客户端root和运维人员属于可信管理范围。普通业务用户不得读取后端私钥/keyring或拥有root等价权限；持有后端凭据的可信root仍可通过原生工具管理配额。
3. **业务挂载固定启用`root-squash`。** 使用预留、排重后的统一非零UID/GID，验证附加组不会带来额外权限，不使用`all-squash`。这用于减少正常挂载上的root误操作，不阻止root主动重挂载或切换身份。
4. **保护实际后端入口。** 核对并实施PD/TiKV强制TLS/mTLS认证，保护Ceph凭据，测试普通UID无法绕过Portal修改配额。其他隔离方案须单独验证；仅按客户端IP放行不足以区分同机普通用户与挂载服务。
5. **新增管理接口限定个人会话。** 新增的身份、目录、配额、任务及审计读写接口均要求有效个人ADMIN登录会话，并校验字段、资源范围及CSRF/Origin。现有`automation-admin/automation-user` Bearer凭据只保留既有监控读取能力，不得借其ADMIN角色读取新的用户、配额或审计记录，也不得调用写接口。控制器限制固定操作和路径，但仍信任Portal转交的人员身份。
6. **页面权限及时生效。** 管理员账号禁用、改密、改角色后旧会话失效；控制器不可用时关闭新增管理接口，保留不依赖它的现有监控。普通用户个人目录查看授权在后续实现时再定义撤权语义。

LDAP管理、Portal写功能和PD/TiKV认证是三项不同工作；任何一项完成都不代表其他两项自动完成。

## 七、最小联合验收集

先完成高风险接口及认证验证，再构建完整功能；不为本任务重复运行全量性能基线，不以反复长时间压测代替权限及配额功能验证。

| 验收主题 | 必须确认的结果 |
|---|---|
| 身份与使用 | Alice、Bob在一台获准客户端上的LDAP解析、登录后的实际UID/GID及组正确；本人目录可写、对方目录不可访问、共享模型只读；覆盖该客户端实际采用的Shell/容器/调度运行方式。第二客户端上的一致性留到第三阶段 |
| LDAP用户选择 | ADMIN可翻页浏览、输入部分用户名筛选已有LDAP账号；输入`Alice`可找到并展示LDAP原始用户名`alice`。登记前重新核对身份及UID/GID；LDAP不可用时不得凭旧列表新增绑定；USER和旧Bearer看不到该列表 |
| 身份服务可用性 | 两个389 DS节点分别能完成在线身份查询与未缓存用户新登录；在隔离环境中分别令其中一个节点不可用，客户端能切换至另一个节点。核对复制延迟及开户、改组、停用在另一节点的可见性；不能只用已缓存身份的登录成功作为通过证据，故障试验不得停止现网服务 |
| UID/GID唯一性 | 受控开户分别经两个节点申请新身份，不出现重复UID/GID；手工指定重复ID的管理路径被限制或明确拒绝；客户端本地账号与预留业务号段排重。DNA自动分号不被当作手工值唯一性的保证 |
| LDAP传输与证书 | 客户端校验两节点服务器证书并通过加密连接认证；证书导入、到期预警、轮流续证及故障切换在隔离环境验证。LDAP暂定单向TLS方案与PD/TiKV双向TLS分别验收；是否要求LDAP客户端证书在S2-0核对 |
| root与凭据 | 业务挂载的root降权生效，普通用户不能读取后端凭据或直接提高配额；独立管理挂载仍可创建目录、chown；本地应急登录保留 |
| 目录登记与交付 | 可以只登记不限额；新目录在配额确认前不交付，交付后仅目标用户可用；已有目录不被搬迁或自动改owner；目录替换、owner异常、越界路径被识别 |
| 原生配额 | 容量/inode分别达到上限后限制增长，同一客户端的两个LDAP用户均受各自目录配额约束；增额恢复写入；记录降额与并发写入、初始化、删除/回收站、rename及硬链接的实际计数行为。跨客户端共同生效留到第三阶段 |
| 网页权限 | 新增用户/目录/配额/审计接口仅个人ADMIN会话可访问，拒绝旧Bearer、USER和匿名；旧会话撤销、跨资源访问、CSRF和重复提交覆盖；现有只读监控回归，不把旧USER整卷授权当成个人额度授权 |
| 任务和恢复 | 提交后断连、worker重启、重复请求、数据库写失败、管理员旧版本冲突均可回读或明确报错，不自动取消配额或盲目重试 |
| 过期数据与空间 | 用可控时钟/临时库验证保留边界、未决保护、删除后旧请求、清理与提交并发、容量门槛和备份轮换；管理库与Portal账号配置只恢复其一时关闭管理写入，核对后重新开放；恢复不重放旧操作，不在真实节点填盘或等待数月 |
| 统计与故障隔离 | 管理员查看的配额用原生计数而非目录统计推算；停掉新增管理服务不删除配额、不切断原有业务IO，第一阶段目录统计及其他监控仍可用；本期不新增个人目录采集 |
| 用户停用 | LDAP停用覆盖实际登录方式及缓存策略；运行中的任务需运维处理；Portal禁用只撤销网页访问，不冒充文件访问撤销，不立即回收仍关联数据的UID/GID |

配额设置成功不等于所有客户端同时完成原子切换，也不承诺零超额；验收记录真实传播及计数特征。本期不以普通用户个人目录三级明细作为交付条件。

功能测试使用专用目录、小额度及有限文件；故障分支在模拟后端或隔离环境验证，不停止现网PD/TiKV/Ceph制造故障。证据保存于`/mnt/c/SunRise/test/`，保留必要结果索引，不收集密码、私钥或无关大数据。

## 八、上线与回退

- S2-0盘点全部业务挂载、统计挂载和运维工具。隔离环境验证认证时覆盖实际PD及Store端点；若以后迁移现有集群，另按全部使用方制定迁移和回退方案。TiKV与Ceph、LDAP各自的凭据和权限分别核对。
- LDAP/SSSD/PAM修改、服务账号及文件权限调整、TLS配置、服务启停和挂载变更，在执行前给出精确操作及回退方法；本计划不等于环境或sudo授权。第二阶段先在隔离环境完成联合验收，不为完成本阶段默认改变157业务挂载或150～152现有PD/TiKV认证。获准复用现有节点时再核对业务窗口，不与性能测试同时变更。
- 若暂时没有足够的隔离后端测试资源，可先完成S2-0及离线开发；真实双节点LDAP、单节点故障切换、mTLS等未在获准环境完成的用例保持“待验证”，不能以单实例或模拟结果代替正式通过，也不为赶进度自动占用现有业务集群。双客户端用例明确移交第三阶段，不作为第二阶段完成条件。
- 试点环境先验证新服务查询、账号隔离与旧监控，再开放试点目录写API；后端防绕过未完成时不开放真实用户的管理写入口。若获准在152安装，先复核其现有监控及业务影响；继续保持当前不开机自启约定，变更需另行确认。
- 回退先关闭新管理写入口，保留真实配额、管理库与审计，核对未决任务；不能为回退删除配额、扩大旧USER整卷查看权或放开凭据。LDAP和TiKV认证的回退分别按维护方案执行。
- 按已定义的期限和容量执行记录清理、SQLite一致性备份与日志轮换；空间压力下暂停新管理变更，不提前删除未决任务或未到期审计。恢复验证使用隔离副本，覆盖授权重新确认和旧预览失效。
