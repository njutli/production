# 第三阶段：客户现场快速部署开发计划书

> 日期：2026-09-22。状态：待开发。
> 方案依据：[客户现场快速部署方案](CUSTOMER-DEPLOYMENT-DESIGN-20260922.md)。本文只安排开发、验证及交付，不授权修改现有集群。

## 一、目标与最小交付

客户运维在指定主服务节点提供一份节点/网络/磁盘/身份配置，检查并批准变更后，由工具完成新集群、客户端及Portal部署，支持失败定位和续跑，不需要手工重演现有实验环境的每条命令。

交付四项：**固定版本部署包、安装向导与CLI、组件安装及核验模块、使用和恢复说明**。先完成CLI闭环，再接入页面；不开发常驻客户端助手、通用配置编排系统、自动扩缩容或集群销毁功能。

### D0先验证什么

只验证会推翻后续设计的少量问题，不先建设大套脚本：

1. 固定交付JuiceFS（含Ceph支持、实际补丁）及同版本最小配额适配验证程序能否正确加载TiKV双向TLS配置；未带证书的普通进程是否被所有实际端点拒绝。优先复用第二阶段Q0的验证结果，不要求此时完整配额控制器已经开发完成。
2. 固定OS上Ceph容器、librados和FUSE依赖是否完整；选定持久化布局、资源预算与客户故障域要求是否匹配。
3. 第二阶段LDAP身份、root-squash、独立管理挂载和配额组件是否已有可集成版本；缺少哪些成品，明确依赖负责人及完成条件。

以上如不通过，先解决或收窄交付范围，不通过放宽认证、使用实验内存盘或修改客户已有账号绕过。

## 四、实现任务清单

### 4.1 配置与发布包

- [ ] 一份带schema版本的inventory；节点角色、网络、设备、身份和凭据引用均显式描述。
- [ ] 锁定二进制、镜像digest、依赖包及签收配置档，记录源码补丁；受信发布校验不只依赖同目录可被一起替换的SHA文件。
- [ ] 只支持冻结组合；离线场景提供全部依赖及经批准的本地镜像仓库方案，不采用开放未认证registry作为默认值。
- [ ] 关闭cephadm默认监控栈，复用Portal监控；镜像源及其CA/拉取权限按运行期依赖保留。cephadm的长期SSH管理账号和root等价权限单独确认，不与部署器临时授权混用。
- [ ] 统一渲染服务unit、监控targets、来源白名单和证书地址，区分业务/管理/统计挂载。

### 4.2 执行与恢复

- [ ] 拟新增`deployctl`提供validate、inspect、plan、apply、status、resume、verify等固定动作；approve绑定不可变计划，运行期Portal不持有执行权。
- [ ] 模块按操作类型拆分，复用安全代码，不复制整段`prepare-all-servers`或Ceph实验脚本。
- [ ] 变更前校验节点/磁盘/路径，写操作逐节点，失败即停后续依赖步骤；可确定安全的只读操作有限并行。
- [ ] 每个操作写前记录意图，有回读方式和重跑判断；只有RUN及真实设备/组件ID、配置匹配的产物才能恢复接续。SSH断连时先确认远端状态；跨RUN也禁止并发修改相同目标。
- [ ] 精确备份受影响配置；结果不明不重做format、不删除数据、不恢复旧密码覆盖新凭据。
- [ ] 安装记录持久化、日志限额、秘密脱敏；执行器退出不影响集群服务，安装恢复不要求浏览器原会话仍存在。

### 4.3 集成与交付

- [ ] Ceph DB/WAL、TiKV、LDAP和管理库全部持久化；不自动初始化未明确选择的盘。
- [ ] PD/TiKV与Ceph认证从新建时启用；普通用户无法绕过配额入口，业务客户端不持Ceph admin keyring。
- [ ] 为批准的客户端分别安全分发TiKV客户端证书/私钥和CA证书，安装时限制私钥文件及目录权限；验证有证书的JuiceFS可连接PD/TiKV、无证书的普通进程被拒绝。第一客户端验证通过后，再批量配置其余客户端的SSSD和JuiceFS；保留本地应急登录，不自研客户端助手。
- [ ] 安装第二阶段的服务账号、控制器和数据库迁移；新目录和配额交付沿用其受控流程。
- [ ] 五页向导复用CLI的输入、计划和状态；USER看不到安装入口、日志或凭据。
- [ ] 形成账号/密钥交付、日常健康、证书更新、重启恢复和主节点故障恢复说明；不是只交付“服务进程已启动”。

## 五、最小验收集

| 类型 | 必须覆盖的用例 |
|---|---|
| 离线校验 | 不同节点/IP/路径渲染；类型、范围与命令注入拒绝；错误角色组合；版本/包损坏；未批准或被修改计划拒绝 |
| 存储安全 | 系统盘、整盘未挂载但子分区/holder在用、同盘别名重复分配、序列号变化、已有集群及同名卷拒绝；无签名但未经客户明确确认可初始化的盘也拒绝；无自动清盘/接管行为 |
| 正常部署 | 一个固定版本环境、3个持久化存储节点、主节点可共置、两个客户端；能新装并获得真实Portal指标 |
| 失败恢复 | 断开SSH、浏览器关闭、主执行器退出、部分安装成功，以及远端成功但成功记录落盘前崩溃；恢复后只核验/续跑，不重复建卷或伪报成功 |
| 身份与权限 | 两LDAP用户两客户端身份一致、私有目录隔离及模型只读；业务root被squash、独立管理入口可交付目录；普通用户不能读凭据或自行提高配额 |
| 配额与管理 | 第二阶段容量/inode配额的设置、回读及两客户端超限；新增管理接口仅个人ADMIN可用，第一阶段既有USER只读监控不回归；未就绪组件明确显示失败或待确认，不把已后置的个人额度页作为门槛 |
| 运行持久性 | 隔离环境逐节点重启后数据/元数据保留；数据盘未挂载时拒绝启动相关服务，避免写进系统盘空目录；Portal/安装器停止不取消既有限额 |
| 离线与清理 | 断公网可完成安装；主节点记录和管理库可恢复；移除临时部署授权后，仍可在隔离环境完成受控服务再部署及镜像拉取，不误删cephadm运行期授权；日志/结果包不含秘密 |

功能验证仅写专属、有限大小的测试目录，记录大小和清理对象；先核对实际挂载和卷UUID，不覆盖固定`hello.txt/random.bin`或历史测试数据。大吞吐和稳定性曲线属于后续性能验收，不作为每次安装的必跑长矩阵。

本地结果统一放`/mnt/c/SunRise/test/portal-stage03/<RUN_ID>/`；客户现场用其批准的持久化目录。按[生命周期规范](../../../prod-deploy/doc/perf-tasks/TEST-DATA-LIFECYCLE-POLICY.md)保留必要证据，不为每一步重复下载全量日志。

## 六、环境操作与回退边界

仅完成本计划和方案文档不需要sudo，也不改变任何节点。真正试验或交付前，必须提供**节点、完整命令、文件/设备目标、影响及恢复方法**供审批。

重点审批包括：新建服务账号和目录、包安装、空盘初始化、unit安装/启停/自启、PAM/SSSD和挂载配置、证书分发、Ceph bootstrap/OSD配置及防火墙变化。对已知业务客户端，禁止把网络、内核参数、Docker/K8s或业务挂载停止混入安装。

先在隔离环境通过D6，再选择客户或获准现场试点；不得因缺少空闲盘而自动清理150～152的现有集群。失败保留现场和记录，优先恢复可达性与原有业务；仅回退本RUN明确修改的配置，已有数据、卷、LDAP身份及配额不自动删除。
