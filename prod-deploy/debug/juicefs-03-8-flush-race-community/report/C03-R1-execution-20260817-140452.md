### 为什么仍不能接受 PR-ready 与完整审计结论

#### 1. runner 来源错链

三次 attempt 的 runner SHA256 分别为：

| attempt | runner SHA256 |
|---|---|
| 1 | `5499d50a2884d287e6a64202743e9fcbef962338698528c214df122864a13b69` |
| 2 | `206cb3390a85f6fad4a8d4cfb0e8a25fff7b72249ce5865f8b36f50657ea8feb` |
| 3（最终报告声称执行版本） | `12c9101bda8914d22f2595eb270699413aea73d881e4c65b19407aa63d9266df` |

attempt 2/3 runner 的 `C03_R1_INPUT` 仍硬编码 attempt 1 input。最终 OUT 校验、复制和归档的是 attempt 1 runner，而不是报告声称执行的 attempt 3 runner；`commands.sh` 和报告中的 runner SHA 也因此指向 attempt 1。archive 无法唯一还原“究竟执行了哪一个 runner”，这是终态证据链的阻断项。

此外，三个 input 目录都出现运行期 `runner.pid`、`runner-stdout.log`，说明冻结 input 在运行后仍被写入，违反输入不可变边界。

#### 2. 若干 gate 没有机械证明报告所声称的条件

1. B/Q 的 count100 和 race gate 主要检查进程 rc，没有机械解析每个测试的精确 PASS 次数；人工复核日志可以形成旁证，但不能替代硬门算法。
2. `git diff --check ... || true`、path guard 后再记录 `$?`，保存的是 `true` 的 0，而不是被检查命令的真实 rc。
3. lint gate 没有把版本查询 rc、lint 前后源码一致性纳入最终判断；Redis gate 没有把 inspect/log 的真实 rc 纳入判断。
4. SOURCE 以及 C02/C03/R1 历史路径缺少执行前后清单比对，不能证明受保护资产在本轮未变化。

#### 3. archive 与终态完整性不闭合

1. archive 内的 `SHA256SUMS` 列出了 archive 实际未包含的四个 build；反过来，archive 中又有两个文件不在 manifest 覆盖范围内。
2. `sha256-check.rc` 在 `set -e` 场景下事后读取 `$?`，不能证明它捕获的是 `sha256sum -c` 的真实返回码。
3. `required_members` 只检查三个文件名，不能证明 archive 成员集合与 manifest 完全一致，也不能证明全部要求证据受 hash 覆盖。

因此，外部 sidecar 的 `archive integrity=YES` 和 `PASS-B-PR-READY-LOCAL` 不能被接受。

#### 4. adaptations 与社区查重仍未闭合

1. `runtime-adaptations.md` 只有 “Runner started”，没有记录真实运行期适配；archive 中的 pre-run 文件也不是 attempt 3 的完整修复历史。
