## 2. 终裁

- **竞态（异步登记 → 首写检查 id==0 → 跳过上传）在 v1.3.1 与 main 均 100% 存在**（插桩：calls=full≈13.1 万、skipped≈99.2%、fired≈0.8%、below=0）。
- **#6311 与竞态无关**：同会话交替实测两基座行为逐位一致（~545 MiB/s 双双崩塌）。早上的"main 3815 健康"是环境新鲜期兜底清仓跟得上的假象；环境退化后 main 与 1.3 一起塌。
- **崩塌链条** = 首写跳过上传（代码级）+ 兜底清仓速度（环境依赖：TiKV/OSD 状态）+ 缓冲节流 ⇒ ~550。唯一直接消除竞态的代码修复 = 本包补丁（同步 NewSlice ⇒ fired=100%）。
- 之前"#6311 是 main 的修复、可 backport"的裁定**作废**（时间错开单跑被环境退化混淆的教训：跨时段单跑对比必须同会话化）。

## 4. 修复边界（如实声明）

- 两修均只覆盖"写请求尺寸 = 块大小"的随机写。写尺寸 < 块大小的纯随机小写在任何挂载上仍走兜底清仓（预存行为，与本缺陷无关）——负控实测 bs=128k@256K = 556 MiB/s。
- 修复后写侧 ~3000 平台由另一面墙（meta 提交率 ~12K/s，TiKV 侧）决定，与本缺陷无关，勿混入 issue。
