# 调优测试 Skill（TUNING）

> 目的：在已签收基线之上，用**最少机器时间**判定一个旋钮是否真的有收益，并给出可复核的效应量。
> 前置：必须先有按 `FULLBASELINE-SKILL.md` 产出的签收基线**和分辨力表**。没有分辨力表就调优 = 拿噪声当收益。
> 依据：`report/基线测试报告-JuiceFS-E6-20260806.md`、R1（档位）/R5（对象数控制变量）
> 前置必读：`SYSTEM-SAFETY-SKILL.md`
> 关系说明：`interleaved-ab-tuning-skill.md` 处理的是**需要重建 layout / format 的旋钮**（block-size、EC profile），那类每轮必须重抽签，只能比分布。本文处理的是**不需要重建 layout 的旋钮**（挂载参数、`ceph config set` 在线项），可以用同实例配对，成本低一个数量级。两者按旋钮类型二选一。

---

## 〇、第一原则

**先问"测得出来吗"，再问"怎么测"。**

调优的分辨力上限由基线的稳定性决定。W2 基线实测：

| 项 | 可检出效应量 | 含义 |
|---|---|---|
| mseqread | **≥1.5%** | 很灵敏 |
| randread | **≥3%** | 好用 |
| randrw | **≥3%** | 好用（注意口径，见 §6.3） |
| randwrite | ≥4%（剔 r1 后） | 可用 |
| seqread | ≥4% | 可用 |
| seqwrite | ≥5% | 勉强 |
| mseqwrite | **≥7%** | 差（存在未定位的离群运行） |

⇒ **预期收益小于该项分辨力的旋钮，不要测**。测出来的"差异"无法与噪声区分，跑一晚等于零信息。若某旋钮的理论收益就在 3-5% 量级，先用配对设计（§三）把分辨力压到 2-3%，再决定测不测。

## 一、旋钮分类（决定实验能不能做）

| 类别 | 例子 | 能否同实例配对 | 成本 |
|---|---|---|---|
| **A. 在线可切** | `ceph config set osd.* <k> <v>` | ✅ 能 | 低（推荐） |
| **B. 挂载参数，不需重建 layout** | `--max-uploads`、`--buffer-size` | ⚠ 需 remount ⇒ **重抽档位** | 中 |
| **C. 需重建 layout / format** | block-size、EC profile | ❌ 不能 | 高，改用 `interleaved-ab-tuning-skill.md` |

### ⚑ B 类的核心难题（必须先想清楚再动手）

改挂载参数要 remount，而 remount **会重新抽档位**（跨实例 median 极差 29.9%）。这意味着：

> **旋钮效应与档位抽签混在一起，单次 A/B 比较毫无意义。**

三条可行路线，按优先级：

1. **优先找 A 类等价旋钮**：能用 `ceph config set` 在线达成类似效果的，一律优先（可同实例配对，成本最低）。
2. **每臂多次挂载，比"分布位移"而非比单值**：每臂 remount N ≥ 3，比较各臂的分布位移。
   - 🔴 **remount 必须按 `A B A B A B` 交错，不是 `AAA BBB`**（2026-08-07，03-3 实测；见 §三）。分臂串行会把时序漂移整体记成臂间差异。
   - 🔴 ~~每次先用探针判档、只保留高档实例~~ —— **这一步基本无效**（2026-08-07，03-1 否证）：探针对其余项的传导增益仅 **0.221**，探针高档**不蕴含**被测项高档。探针只能确认"randread 自身在高档"。
   - 成本参考：randread 高档命中率约 **61%**（平均挂 1.6 次中一个）⇒ 每臂 3 个高档实例约需 5 次 remount。
3. ~~**门控 + 配对 + 探针归一化**~~ 🔴 **已否证，作废**（2026-08-07，03-1）：留一法得探针与其余项 **r = −0.1291**、传导增益 **0.221**、SNR 相差 **22 倍** ⇒ 不存在可用的传导系数，读项也不例外。详见 §4.2。

## 三、核心设计：同实例 A/B 交错（⚑ 2026-08-07 升级，原 A-B-A 降为退化下限）

```
门控（randread 探针命中高档）
  ↓  固定实例，全程 SKIP_REMOUNT=1
A₁ B₁ A₂ B₂ A₃ B₃   ← 交错，每臂 ≥3 段，只跑受影响项
  ↓
效应量   = median(所有 B 段) / median(所有 A 段) - 1
时序漂移 = Spearman(段序, 值)  ← 必须报，用来证明交错确实需要
```

### ⚑ 为什么必须交错（03-3 实测，不是理论顾虑）

同一实例、同一配置、日间 4.5h 窗口：

| 量 | 值 |
|---|---|
| 时序漂移（randread 首→末） | 1862.8 → 1830.7，**1.72%** |
| Spearman(段序, 值) | **−0.771**（单调下行，不是随机抖动） |
| 漂移最低点 | 午后 14:07-14:52 外部负载峰 |
| **交错后臂间残差** | **0.233%** |
| **漂移抵消率** | **≈87%** |

**1.72% 已超过 mseqread 的分辨力 1.5%** ⇒ 分臂串行下，什么旋钮都不动也能"测出"显著收益。

**交错生效的判据**（03-3 全部满足，可作为模板）：

| 判据 | 03-3 实测 |
|---|---|
| 6 个 median 排序应**完全交织**、无分层 | `B A B A B A` ✅ |
| Mann-Whitney U 不显著（n₁=n₂=3 需 U=0 或 9 才显著） | **U = 7 / 9** ✅ |
| 两项效应量**符号相反** ⇒ 纯噪声特征 | mseqread **+0.138%** / randread **−0.233%** ✅ |

**⚑ 时段是隐含前提**：03-2 夜间测得 randread 无 lag 依赖（+0.091），03-3 日间测得 **−0.771** —— 同一系统、相反结论。⇒ **底噪与门槛只在采集时段内有效**；两臂必须落在同一时段窗口（交错天然满足），跨时段历史值不可直接相减。

要点：

| 要点 | 理由 |
|---|---|
| ⚑ **交错 ≥3 对（A B A B A B）** | 首选。可抵消 ≈87% 的时序漂移，并能用交织度/U 检验/符号一致性三重自证 |
| **A-B-A 三点是退化下限** | 仅当时间预算不足时用。它只能做**线性**漂移校正，对 03-3 那种非线性负载峰无能为力。A↔A' 的差值即本次漂移底噪；若 \|A'−A\| 接近 \|B−A\|，结论作废 |
| 🔴 **禁止 A-B 两点** | 无任何漂移估计量 |
| **全程同一挂载实例** | 消掉 ≤30% 的档位噪声，这是配对设计的全部价值 |
| **首运行作废或对称安置** | 首运行有冷启动效应（seqread r1 hit 85%）与 randwrite 整体 +5% 偏高 |
| **只跑受影响项**（`ITEMS=...`） | 写侧旋钮不必跑 seqread/mseqread/randread；7 项全跑一次 3h40m，裁到 3-4 项可省一半以上 |
| **臂间不 remount** | A 类旋钮天然满足；B 类做不到，见 §一 |
| **每臂 ≥2 轮** | 单轮无法算 L2，无法判该臂数据是否可信 |

命令模板（A 类旋钮，写侧项）：

```bash
# 臂 A（基线）
ITEMS="randrw seqwrite mseqwrite randwrite" SKIP_REMOUNT=1 \
  bash FULLBASELINE_V4.sh T1_A1 180 2

# 切旋钮（在线，记录切换时刻与返回值）
sudo ceph config set osd.<N> <knob> <new>     # 或 tell，视旋钮而定
sudo ceph config get osd.<N> <knob>           # 回读确认生效

# 臂 B
ITEMS="randrw seqwrite mseqwrite randwrite" SKIP_REMOUNT=1 REF_LABEL=T1_A1 \
  bash FULLBASELINE_V4.sh T1_B1 180 2

# 恢复旋钮 + 臂 A'
sudo ceph config set osd.<N> <knob> <orig>
ITEMS="randrw seqwrite mseqwrite randwrite" SKIP_REMOUNT=1 REF_LABEL=T1_B1 \
  bash FULLBASELINE_V4.sh T1_A2 180 2
```

**每次切旋钮后必须回读确认**，并把切换时刻记进日志 —— 事后要能证明"某轮跑在哪个旋钮值下"。

## 四、判定

### 4.1 效应量与显著性

```
A_ref    = mean(median(A), median(A'))
效应量   = median(B) / A_ref - 1
漂移底噪 = |median(A') / median(A) - 1|
每臂 L2  = (max-min)/median   （该臂内轮间极差）
```

判定表：

| 条件 | 结论 |
|---|---|
| \|效应量\| < max(漂移底噪, 该项分辨力) | **无差异**（不是"有小幅提升"） |
| \|效应量\| ≥ 2 × 漂移底噪 且 ≥ 分辨力 且 每臂 L2 达标 | **有效应**，报数 |
| 任一臂 L2 越界 | 该臂作废，补跑；不许拿越界数据下结论 |
| 漂移底噪 > 分辨力 | **本次实验无效**（环境在漂），重做 |
| 出现 `forced-mount` | 配对断裂，**全部作废** |

> **不要把"落在噪声内"写成"略有提升"。** 这是调优报告最常见的失真来源。

### ⚑ 4.1.1 判据集：实际生效门槛 = max(分辨力, 2× 同实例底噪)

代入 03-2 实测同实例底噪（F13）：

| 项 | 同实例底噪 | 2× 底噪 | 分辨力 | **实际生效门槛** | 状态 |
|---|---|---|---|---|---|
| mseqread | 0.50%（lag1） | 1.00% | 1.5% | **1.5%** | ✅ 判据集主力 |
| randread | 1.30% | 2.59% | 3.0% | **3.0%** | ✅ 判据集 |
| **seqread** | **3.89%** | **7.78%** | 4.0% | **7.78%** | 🔴 **移出判据集**：底噪门槛已超过分辨力，该项无判别力 |
| 写侧四项 | ⏳ **未测** | — | 4-7% | ⏳ **无可用门槛** | 🔴 03-4 采集中，出结果前写侧 A/B 不可判定 |

**⚑ mseqread 的 lag 依赖（关键排期约束）**：底噪从 lag1 的 **0.50%** 涨到 lag8 的 **1.69%**（Spearman **+0.939**）⇒ **同一臂相邻轮次的间隔越大、门槛越高**。交错设计要把同臂相邻轮的间隔压到最小，否则 1.5% 的门槛保不住。

### 4.2 🔴 探针归一化 —— 已否证，禁止使用（2026-08-07）

> ~~若不得不跨实例比较（B 类旋钮），每臂先跑 75s randread 探针 `p_i`，用 `p_i / p_ref` 归一化该臂读项测量值。~~
> ~~限制：R4/R5 已证 randread 与写侧历史完全解耦，所以探针可归一化读项，不能用来归一化写项。~~

**03-1 否证结论**（留一法，去掉 X1+X2 后）：

| 量 | 值 | 含义 |
|---|---|---|
| 探针 ↔ 其余项相关 | **r = −0.1291** | 无相关，且符号还是负的 |
| 传导增益 | **0.221** | 探针涨 10%，被测项只跟 2.2% |
| SNR 比 | **相差 22 倍** | 归一化引入的噪声远大于它消掉的 |

⇒ **不存在可用的传导系数，读项也不例外**（原文"可归一化读项"不成立）。跨实例比较只能走"每臂多次交错 remount 比分布位移"（§一 路线 2）。

**探针剩下的合法用途只有三个**：
1. 确认**实例同一性** —— 硬判据是 **pid + starttime_ticks**，**不是带宽值落在某区间**
2. 确认实例健康、randread **自身**落在高档
3. ⚑ 作为**外部负载协变量**记录（见 §十）

### 4.3 r1 规则（写项必须遵守）

`randrw` / `randwrite` 每轮后都做 `gc --compact`，**r1 是"池刚复位"的特殊状态**：`randrw` 的 r1 是唯一受控状态（历史签收取的就是 r1），`randwrite` 的 r1 系统性偏高。

> 调优时两项口径必须与基线一致：**r1 单独记录，L2 与效应量都用 r2 起的轮次**（每臂 2 轮时意味着至少要跑 3 轮才有 2 个有效轮 —— 排期时算进去）。

### 4.4 口径

`randrw` 有"读侧"（`FULLBASELINE_V4.sh`，只取 `direction==0`）与"读写合计"（debug 脚本 / `r5chk.py`）两种算法，**差 2 倍**。调优前后必须用同一口径，报数时写明是哪个。

## 五、写侧旋钮的额外约束：对象数

R5 证实的唯一控制变量是**当前池未回收对象数**（r=−0.807；累计写入 r=−0.159、时间序 r=−0.136）。因此写侧调优的每一轮都要受控：

| 规则 | 值 |
|---|---|
| 轮前 objects 安全上限 | **≤3.11M**（`compact` 后最多 2 轮，判定只认第 1 轮） |
| 塌陷拐点 | objects ∈ (3.78M, 4.40M] |
| 早期报警 | **轮内 q1→q4 趋势跌破 −5%**（均值仍健康时趋势先转负） |
| 可逆性 | 恢复率 105% ⇒ `gc --compact` 可完全复位到 2.36M。⚑ **2026-08-07 独立确认**：03-4 首轮 randrw（写入 212 GiB / 生成 0.868M 对象）经 `aggressive_cleanup` + `gc --compact` 后回到 **2,359,530**，与基线 2,359,529 只差 **+1** |
| ⚑ 回收速率（负载下实测） | **≈3216 对象/秒**（03-4 首个排空窗 0.868M ÷ 270s，为下界）。F14 观测区间 2000-6400 |
| 🔴 ⚑ **两个常数别混用** | **① 池内平均对象大小 = 256 KiB**（`STORED÷objects`：576GiB/2.36M，post 4.1TiB/17.03M=258KiB）。**② 每新增 1 对象所需写入 = 292 KiB**（R5 直接实测：211 GiB ⇒ objects **+757k**）。<br>**估算"写入 N 字节会新增多少对象"必须用 ②**；用 ① 会**高估 ≈14%**。差值来源：约 12% 的写落在已有对象上（覆写），不产生新对象。<br>⚠ 2026-08-07 在 03-4 任务书里真实踩过这个坑 |
| ⚑ 排空/工期估算优先用**字节口径** | 排空总量与回收速率都要乘同一换算常数，比值里约掉 ⇒ **字节口径不依赖该常数**。实测 **0.785 GiB/s**（03-4 首个排空窗 212 GiB ÷ 270s，为下界）。对象口径 ≈2800 对象/秒，两者互为交叉校验 |
| ⚑ `gc --compact` **不回收待删切片** | 输出里的 `pending delete` 不会被 compact 清掉；若跨轮累积，排空后的"地板"会单调抬升 ⇒ 长跑须逐轮记录地板值与 `pending delete` |
| `compact` 成本 | `秒 ≈ 1.95e-4 × 回收对象数`（误差 6%）⇒ 单轮回收约 148s |
| 空间放大 | 1.84-1.88×；每写入 292 KiB 产生 1 个新对象 |

⇒ **每轮前后都要记 `ceph df` 的 objects**，并在报告里给出"轮前 objects"列。轮前 objects 不同的两个测量值不可直接比较。

## 六、时间预算

| 单元 | 耗时 |
|---|---|
| 门控（randread 75s × 1） | ≈16 min |
| randrw 1 轮（含 cleanup） | 8 min |
| randwrite 1 轮（含 cleanup） | 11.3 min |
| seqwrite / mseqwrite 1 轮 | ≈4 / 4 min（含 `compact_cooldown`） |
| A-B-A 三臂 × 4 写项 × 3 轮 | ≈4.5-5 h |
| A-B-A 三臂 × randrw only × 3 轮 | ≈1.5 h |
| ⚑ **交错 A B A B A B（6 段）× 4 写项 × 3 轮** | ≈9-10 h（交错是 A-B-A 的 2 倍段数） |
| ⚑ **交错 6 段 × 读项（03-3 实际）** | ≈4.5 h（含门控与实例校验，实测） |
| `reset_state` 的 `gc --compact` | 首次 ≈46s；经历一次全量写后 ≈10 min |

**排期建议**：一次实验只测**一个旋钮**（或一个旋钮的两档）。同时改两个旋钮，出了差异也不知道是谁的。要测组合，必须先各自单独测过（A / B / A+B / 基线，4 臂）。

### T2 读侧旋钮（方法学有坑，未定案）

`--max-readahead` 类需 remount，**会同时污染门控探针**（探针本身就是 randread）；而探针归一化本身已在 §4.2 被否证作废 ⇒ 只能走"每臂多次**交错** remount 比分布位移"，成本高。备选是找 `ceph config set` 类在线读侧旋钮（A 类，需另行授权）。

⚑ **`seqread` 已移出判据集**（底噪 3.89% ⇒ 门槛 7.78% > 分辨力 4.0%，见 §4.1.1）⇒ 读侧旋钮的判定只能靠 `mseqread`（1.5%）与 `randread`（3.0%）。但 `randread` 同时是门控探针，读侧 B 类旋钮会把它一起改掉 ⇒ **实际只剩 mseqread 一个判据项**，这是 T2 方法学的核心困难。

## 十、何时该停下来汇报，而不是继续测

| 情形 | 动作 |
|---|---|
| 门控 5 次不中 | 停下汇报，**不许放宽区间** |
| ⚑ **不要把探针当看门狗** | 03-3 表明日间 4.5h 内 randread 就能跌 1.72%，最低点 1830.7 距高档带下界 1830 只剩 **0.04%** 余量。长跑中设"越界即中止"**必然误报** ⇒ 把探针当**外部负载协变量**记录，中止线放到远离常态波动处（03-4 取 single-run median < **1700**，落在 F3 多档 1714 与 1334 之间的空隙） |
| 漂移底噪 > 分辨力 | 停，本次无效 |
| 出现 `forced-mount` | 停，配对断裂 |
| 轮内 q1→q4 趋势跌破 −5% | 停，池对象数越界，先 `compact` |
| `ceph health` 非 OK | 立即停 |
| 效应量落在噪声内 | **这就是结论**（"无收益"是有价值的结论），不要加样本硬凑显著性 |
| 脚本连续报错 | 停下让执行方直接调试，不要盲改 |
