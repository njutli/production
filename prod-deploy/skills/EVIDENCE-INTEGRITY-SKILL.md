## 一、有效带宽口径（唯一主口径）

### 1.1 三步法

```text
① 起点对齐    实际 timed-I/O 起点 = fio 报告完成时刻 − run= 实际毫秒数
              ⛔ 禁用 fork 时刻 / 脚本登记的 fio_start / sampler 启动时刻
② 重采样      每份 per-job interval log 的每个区间，按与自然秒的【重叠时长】加权摊到各自然秒
              ⛔ 禁止把第 N 行当第 N 秒
③ 逐秒求和    只保留当秒 job 数齐全的样本，再对全部 job 求和
```

必须同时输出：正式窗（如 `[15,175)`）的 mean / median / 秒级 CV / P10 / P90，
以及 W1--W4（各 40 s）的均值与 `W4/W1`。

### 1.2 参考实现（伪码，语义即契约）

```python
# 输入：某 item 的 N 份 *_bw.*.log（fio --log_avg_msec=1000 的 interval-average）
#      fio 文本里的完成时刻 t_done 与 run= 实际毫秒 run_ms
t0 = t_done - run_ms / 1000.0            # ① 实际 timed-I/O 起点

per_sec = defaultdict(lambda: defaultdict(float))   # sec -> job -> MiB/s 加权累加
per_sec_w = defaultdict(lambda: defaultdict(float)) # sec -> job -> 权重累加

for job, log in logs.items():
    prev_ms = 0
    for ms, val_KiBps, *_ in parse(log):             # fio log 的时间列是相对毫秒
        a, b = prev_ms / 1000.0, ms / 1000.0         # 该区间 [a,b)
        prev_ms = ms
        for sec in range(floor(a), ceil(b)):         # ② 与自然秒求重叠
            ov = min(b, sec + 1) - max(a, sec)
            if ov <= 0:
                continue
            per_sec[sec][job]   += val_KiBps / 1024.0 * ov
            per_sec_w[sec][job] += ov

series = {}
for sec in sorted(per_sec):
    if len(per_sec[sec]) != len(logs):                # ③ job 数不齐的秒丢弃
        continue
    series[sec] = sum(per_sec[sec][j] / per_sec_w[sec][j] for j in per_sec[sec])
```

⚑ fio 的 bw log 单位是 **KiB/s**，第一列是**相对毫秒**。两者都必须在代码里注明，
历史上多次因单位/基准搞错而得出"超网卡线速"的假值。

### 1.3 起点敏感性三算（强制）

分析器必须支持把起点人为偏移后重算，并在 Gate 0 中断言：

| 偏移 | 必须的表现 |
|---|---|
| `±1 s` | 正式窗结果变化 **<1%** |
| `+58 s` | **必须显著改变 W1--W4** |

若 `+58 s` 结果几乎不变，说明窗口逻辑没生效（03-20B-R2 正是踩在这里）。

### 1.4 恒等式自检（写侧可用）

```text
在飞 meta ≡ 4 × BW(MiB/s) × 延迟(s) × (meta/写op)
```

15 个 256K cell 上最大误差 0.017%。它只能作**自检**：如果三个量对不上，说明某个计数器取错。
⛔ **不得把它变形成判据**（例如 `BW×lat/inode`）——那是同一个恒等式的重排，不携带新信息。

### 1.5 ⛔ 禁止清单

- fio summary 作主口径（历史误差：03-19 报 24%--26%，正式窗真值 10%--13%）
- 单 job 或单文件数值 × numjobs 外推
- 挑最好的窗口 / 挑轮次
- 跨日终值直接相减
- 把 randrw 读写相加后与单向目标比
- 超网卡线速（100GbE ≈ 12500 MiB/s）的均值

## 二、多臂设计：平衡顺序 + 噪声底自校准

### 2.1 交错粒度：能按轮就不要按 block

实证数据（V141R/V141P，两个版本各占据连续时段）：

| 项 | 真值 | 实测臂间差 |
|---|---|---|
| seqread | **0**（补丁只动写路径） | **−5.25%** |
| mseqread | **0** | −2.26% |
| randread | **0** | +1.03% |

三个纯读项真值必为 0，实测跨度 **6.27 pp**，而轮内 CV 只有 **1.1%**。
⇒ 这是**块级系统偏置，加轮数消不掉**。必须把交错粒度降到轮级（十分钟量级）。

### 2.2 ABBA-BAAB：一阶抵消一切单调漂移

```text
R01=A  R02=B  R03=B  R04=A  |  R05=B  R06=A  R07=A  R08=B
```

- **跨臂配对 4 对**（全相邻）：`(R01,R02) (R04,R03) (R06,R05) (R07,R08)`
- **同臂相邻对 2 对**：`(R02,R03)` 同 B、`(R06,R07)` 同 A —— **真值恒为 0**

平衡性必须在报告中复算并列出：A 占位 `{1,4,6,7}` 均值 **4.5**，B 占位 `{2,3,5,8}` 均值 **4.5**
⇒ 时间、对象数、compaction 债、温度等一切对轮序单调的漂移**一阶完全抵消**。
每个 4 轮 block 内各臂各 2 轮，block 内也平衡。

⛔ 单个 ABBA block 不够；⛔ 每臂占据连续时段（序贯设计）一律不接受。

### 2.3 噪声底自校准：边界由数据推出

```text
效应量   D_med = median(D_1..D_4),  D_k = BW(B臂)/BW(A臂) − 1
噪声底   ε     = max(|N1|, |N2|)    N = 同臂相邻对的相对差
判定边界 M     = max(工程边界, 2ε)
```

- `D_med ≥ −M` 且 ≥3/4 配对同向 且 `ε < 工程边界` ⇒ **NON_INFERIOR**
- `D_med < −M` 且 ≥3/4 配对同为负 ⇒ **MATERIAL_REGRESSION**
- `ε ≥ 工程边界` ⇒ **RESOLUTION_INSUFFICIENT**（只给上界，⛔ 不得宣告"等价/非劣"）
- 其余 ⇒ **INCONCLUSIVE**

⛔ **禁止先设边界后测噪声。** U141 把边界设在 `±3%`，而该批次块级偏置实测 `5.25%`
——判据比噪声还细，无分辨力。

### 2.4 零假设对照优先于统计

若被测变量在**物理上不可能**影响某些测试项，这些项就是零假设对照，
其实测偏差直接量化该批次的偏置底噪。任务书应主动设计这类对照。

反面教材同时也是正面示范：V141R/V141P 的补丁只改 `pkg/vfs/writer.go`，
所以三个纯读项成了免费的零假设对照，直接暴露了 `±5.25%` 的底噪——
**这批数据最有价值的产出不是它想测的效应，而是它意外测出的噪声底。**

### 2.5 状态型混杂必须显式建模

对象数、pending compaction、文件资产 mtime 等随轮次单调变化的量：

1. 逐轮记录为协变量（数值，⛔ 不得是字面 `GiB`）；
2. 报告给出两臂起点的平衡性检验；
3. 若相关系数显著（例：U141 randrw `r(obj,BW) = −0.863`，斜率 −33.5 MiB/s per M obj），
   臂效应与该量共线不可分离 ⇒ 判 `EVIDENCE_INVALID`；
4. ⛔ 任务书不得出现与硬门矛盾的软化条款（U141 的 "SOFT-PASS 也算通过" 与 S15 硬门直接冲突，
   执行方遵守了前者，整批作废）。

## 三、非性能证据门 vs 性能端点（必须分离）

| 类别 | 内容 | 能否删样本 |
|---|---|---|
| **非性能证据门** | sampler 覆盖率、身份指纹（PID/starttime/exe md5/CEPH_CONF/max_read）、集群健康与 PG、容量、内存/swap、reset 与清理闭环、I/O 错误、缺 log、文件资产一致性 | **能** |
| **性能端点** | 带宽、CV、`W4/W1`、延迟 | **不能** |

> 教训出处：03-22b 把 `CV≤10%` 同时当证据门。当研究目标本身包含"能否降低 CV"时，
> 控制臂真实不稳定反而使 analyzer 拒绝出数、整个 RUN 失去回答该问题的能力。

推论：**验收门**（部署是否可接受）与**有效性门**（数据是否可信）是两件事，⛔ 不得共用一个阈值。

## 四、RUN 有效性状态机

```text
                   ┌── 任一非性能门 FAIL / 缺臂 ──→ EVIDENCE_INVALID  （只作工程观察）
                   │
Gate 0 PASS ──→ 执行 ──┼── ε ≥ 工程边界 ────────→ RESOLUTION_INSUFFICIENT（只给上界）
                   │
                   ├── 方向一致性 <3/4 ────────→ INCONCLUSIVE       （只报逐对值）
                   │
                   └── 全通过 ────────────────→ VALID              （可作正式效应量）
```

### 4.1 硬性禁止

⛔ 同 RUN 热改脚本后按 normal 签收 · ⛔ 换 RUN_ID 重来 · ⛔ 补样替换 ·
⛔ 把无效 RUN 点值与有效 RUN 拼成新效应量 · ⛔ 门失败后改挑有利判据

> 最后一条的实例：U141 randwrite 的 G8 流形门失守（8/8 残差全负、均值 −1.82σ、A 臂越界），
> 却仍想用 `|Δresid| = 54.5 ≤ 74.8` 宣告"等价"。预注册规则已写明门失守即降级为不可判。

### 4.2 门必须标定在可达水平

03-20B / R1 / R2 / 03-22 / 03-22b / 首次 03-22c **连续 6 次**
"形式上 `EVIDENCE_INVALID`、正文仍引用其工程结论"。
**一道总是失败的门不携带信息。** 若一类门连续两次全 RUN 失败，
应先修门再上环境，⛔ 不得靠"这次也失败但结论仍成立"继续。

### 4.3 失败即保留现场

不卸载、不删目录、不清 sampler、不 kill。
⛔ `fusermount -uz` · ⛔ `umount -l` · ⛔ `losetup -D` · ⛔ `rm -rf` ·
⛔ `pkill`/`killall`/`fuser -k`/模式 kill · ⛔ kill mount PID

### 4.4 incidents 账本

append-only，任何异常/修复在动作**前后各记一条**，⛔ 不得改写历史行。
**事后汇总里出现账本没有的修复项，视为账本无效**（首次 03-22c：账本 2 行，汇总列了 4 项修复）。

## 五、离线 Gate 0

### 5.1 铁律

**Gate 0 未过 ⛔ 禁止 SSH / sudo / mount / fio / ceph / juicefs 任何一条。**
Gate 0 本身不连接环境、不写数据。失败只许改脚本并重跑 Gate 0。

### 5.2 四个必做项

| # | 项 | 内容 |
|---|---|---|
| 1 | 静态检查 | `bash -n` + `bash -u -n` + shellcheck（有则跑）+ 自 grep 明文口令 |
| 2 | 缺陷类覆盖断言 | 逐条断言覆盖 `skills/fixtures/known-defect-classes.tsv`，`severity=CRIT/HIGH` 必须全覆盖 |
| 3 | **分析器在历史归档上自证** | 用已知答案的旧数据跑一遍，见 5.3 |
| 4 | 驱动脚本合成 fixture 自测 | 每条硬门都要有一个"应当 FAIL"的输入 |

### 5.3 ⭐ 分析器自证：用已经花过钱买到的数据

这是 Gate 0 里性价比最高的一项，**零环境成本**：

1. 选一个已有归档，其 fio 汇总值是已知答案；
2. 对无明显轮内衰减的项（读项、seqwrite），正式窗 median 与 summary 偏差必须 **≤2%**；
3. 对有衰减的项（randwrite/randrw），允许偏差大，但必须 `W1 > W4` 且 `W4/W1 ∈ (0,1]`；
4. 打印实际 I/O 起点与登记起点之差；
5. 做 §1.3 的起点敏感性三算。

### 5.4 缺陷类目录的用法

`skills/fixtures/known-defect-classes.tsv` 字段：

```text
id  severity  class  symptom  origin  fixture_assertion  static_check
```

- `static_check` 非空的条目可直接做 grep 级静态断言；
- `fixture_assertion` 描述该条必须被什么输入证明；
- **新踩的坑必须追加进该文件**，否则下一个任务会重犯。
  追加时必须填 `origin`（哪份报告哪一节），这是它区别于普通 checklist 的地方。

### 5.5 R01 后冻结

正式矩阵首轮开始后**脚本一个字节都不许改**。
若必须改：当前阶段记 `EVIDENCE_INVALID` → 重跑 Gate 0 → **从该阶段首轮重新开始**。

## 六、隔离台架合同（跨 arm 状态归一）

来源：03-22c §9.3，已在正式 RUN 中生效。适用于任何"每臂必须从相同状态起跑"的实验。

1. **一次 layout 生成 immutable seed**，每 arm 只 restore/clone
   ⇒ 消除 layout lottery 与数据集变化；
2. **fresh 必须覆盖四层**：metadata namespace、本地文件系统、旧实例目录、loop/ext4 与可用空间。
   ⚑ **只换 data-dir 名称不算 fresh**（03-22 R05 因复用 logs 目录跨 arm 累积容量而炸）；
3. **每 arm 后独立 GC return**：核对 `valid=<基线>`、`leaked=0`、pool 对象数回归 ±门限。
   ⚑ `juicefs gc --compact` 对**活数据无效**——U141 有 5 次逐字节零效果；
   要排空必须先删载荷文件再 `gc --delete`；
4. **容量前置合同**：每 arm 前后核对 per-role 总量/已用/可用/旧目录，
   预计增量必须小于可用并保留明确余量；
5. **sampler 生命周期以负载进程结束为准**，另设有余量的总 watchdog；
   超时与 sampler 自身失败必须**分型**（03-22 R05 把超时误报成 sampler failure）。

## 七、第二方独立复算（强制）

### 7.1 分工

| 角色 | 交付 |
|---|---|
| 执行方 | 原始数据 + 逐门 PASS/FAIL 清单 + `incidents.tsv` |
| 第二方 | 全部统计量、效应量、判定 |

⛔ 执行方**不算**效应量 / CV / 中位数，**不下**"有效/等价/退步"结论，**不挑**轮次。

依据：独立复核推翻或订正了 **6/6** 份报告的头条结论——

| 报告 | 原结论 | 复核后 |
|---|---|---|
| 03-19 | "稳定性门通过"、增益 24%--26% | `STABILITY_FAIL`（8/8 arm CV 35%--51%）、真值 10%--13% |
| 03-20A | 相关 OSD 字段"此版本不存在" | 解析路径/key 错误，字段存在 |
| 03-20B | 挂载指纹 PID 3157416 | 实际 3387147；行数与文件数也有误 |
| 03-20B-R1 | 覆盖率全 PASS、归档完整 | 内层 manifest 8 文件不一致；覆盖率把行数当 scrape |
| 03-20B-R2 | "执行成功、55/55 全 PASS" | 时间轴错 58 s，校正后 W4 覆盖 38/40 FAIL |
| 03-22c | "D1 降低物理 NVMe await" | await 实际**升高**；稳定性应归到 Raft sync 被隔离 |

### 7.2 归档必须可被独立重算

含实际执行脚本**全文**与 md5、冻结 manifest、内层 `SHA256SUMS` 自校验全 PASS、
Gate 0 产物、`incidents.tsv`、授权账本。
⛔ 只留截断的 md5 声明或 `.pid` 文件不算可追溯（03-20B 因此无法复原被执行版本）。

### 7.3 订正必须提到文档开头

⛔ **禁止把裁决写在附录而正文仍留错误数字。**
反面教材：03-19 §1/§4.3/§6 至今写着"增益 24%--26%""稳定性门通过"，而 §9 才给出
`STABILITY_FAIL` 与 `10%--13%`；引用摘要者必然拿到错数字。
正确做法 = 在标题或"文档状态"表给出**机器可读的 verdict 行**，例如：

```text
| VERDICT | STABILITY_FAIL_WITH_DIRECTIONAL_SIGNAL |
| 主口径效应量 | 10%--13%（正式窗，非 fio summary） |
```

## 八、分阶段执行的粒度（协调成本控制）

03-22c §9.3.2 已量化：前期"每小步停下、一句指令、执行后回传"产生大量重复上下文，
**边际信息收益偏低**；而真正高价值的投入集中在事前合同审查、无效 RUN 审计、
时间线独立复算和跨源归因。

因此推荐粒度：

| 停点 | 理由 |
|---|---|
| Gate 0 之后 | 未过不许碰环境 |
| 前置归一化 + 首轮之后 | 校时长、核兼容性/身份门 |
| **每个 phase 之后** | 一个 phase 废掉不该拖累下一个；前序结果可能决定后续 phase 是否需要跑 |
| sudo 存储变更 / 生产停启 / 失败现场 | 安全 |

- **phase 内部不要停**：中途停下重挂会引入新的时间偏置，正好破坏轮级交错的意义。
- **phase 之间必须停**：这是唯一有决策价值的停点。
- read-only 采集、单 arm 内部步骤、GC 验证、归档由冻结 driver 自主完成。

## 九、性价比结论（决定保留什么、删什么）

| 类别 | 判断 | 依据 |
|---|---|---|
| 口径类（起点对齐 / per-job / 正式窗 / 四窗 / GC return） | **极高，永久保留** | 实际反转或修正过机制结论与效应量 |
| 第二方独立复算 | **极高，永久保留** | 6/6 命中 |
| 安全类（容量 / 身份 / 生产指纹 / 失败保留现场） | **高，保留** | 拦住了 03-22 R05 的容量事故 |
| 治理类（逐步授权 / 账本 / 因协议作废重跑） | **原则正确，实现须压缩** | 3 个无效 RUN 里 2 个死于治理而非测量 |
| 逐小步人工往返 | **删** | 协调 token 高、边际信息低 |
| 为修仪表重跑相同负载 | **删** | 12 arm 里 4 次只为修仪表，全部可离线发现 |

⚑ **最重要的方法论结论不是"门越多越好"**，而是：
**保留能够改变证据有效性或保护生产的门，自动化已经稳定的机械步骤，
删除没有新增信息的逐小步人工往返。**
