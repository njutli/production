## 五、是否需要在新集群测全内存盘？

**评估结论：不需要。**

理由：
1. **写类已撞墙**：新集群千兆限速 seqwrite=114 / randwrite=117 / layout=114 ≈ 1Gbps 理论上限。全内存盘不会提升已撞墙的指标。
2. **读类已超老集群全内存盘**：新集群 randread(default)=90.9 vs 老集群全内存盘 randread(default)=55.7，新集群 NVMe SSD + 双网分离已优于老集群全内存盘。全内存盘不会进一步提升（瓶颈在网络不在磁盘）。
3. **新集群已有 DB/WAL on tmpfs**：新集群的 DB/WAL 已在内存盘上，仅 DATA 在 NVMe。千兆限速下 DATA 的磁盘 I/O 不是瓶颈（网络是瓶颈）。

## 九、数据可信度复核修正（2026-07-15）

> 复核了全部 4 组原始 fio 输出 + bw_log 时序 + env/ceph-status 快照。过程扎实，但三处判读须修正。

### 9.1 过程可信（保留）
- 每组 `env-snapshot.txt`（测前 HEALTH_OK + TBF=1Gbit 仅发 58KB）+ `ceph-status-after.txt`（测后 TBF 已发 211GB、overlimits 2.4 亿次）证明**全程真实限速**，非配置摆设。
- 限速态 MON/OSD 全在 10.114.1.x，HEALTH_OK 贯穿；JuiceFS 版本含 loadRange 修复。
- 写类（seqwrite/randwrite/mseqwrite/layout ≈114）bw_log 稳定，撞 1Gbps 墙（理论 118 MiB/s），**物理合理，可信**。

### 9.2 修正一：千兆读类判读——聚合天花板是 354 不是 118（**订正**）
**关键**：TBF 只加在 **3 个 Ceph 节点各自的 eno12409**，**未加在客户端 157**（见 `limit-bandwidth.sh` §158）。客户端从 3 节点并行读，**聚合读上限 ≈ 3×118 = 354 MiB/s**，而非 118。因此多数读数在物理上是**成立**的：

| 项 | 上报值 | 判定 | 依据 |
|---|---|---|---|
| default mseqread | 182 | **可信** | < 354 聚合线；16 job 跨 3 节点并行 |
| ra0 randread | 181 | **可信** | < 354；EC 分片跨节点并行读 |
| default randread | 90.9 | **可信** | 远 < 354 |
| ra0 seqread | 56.7 | **可信** | 单流延迟受限真值（≈71 附近） |
| default seqread | 147 | **存疑（预读并行）** | 单流 psync iodepth=1 理论≈71，147 属默认预读跨 3 节点预取放大；非本地缓存假象，但也非"纯单流"真值 |

→ 原判"读类整体缓存假象"**推翻**。真正需注意的仅 default seqread=147：单流本应 ~71，翻倍来自预读把后续对象跨节点并行预取（default readahead 的作用），这也解释了 ra0 单流 seqread 掉到 56.7（关预读=失去并行预取）。**结论：千兆读类数据可用，仅 default 单流 seqread 含预读并行加成，判读时注明即可。**

> ⚠️ 早前误按 118 单链上限判"缓存假象"，实为 354 聚合上限，已订正。下方表格标注同步更新。

### 9.3 修正二：randrw R/W 分列是 fio 队列测量偏差（关闭 §8 无效结论）
- 128 job × iodepth 128 = 16384 并发压 1Gbps，队列灾难性积压：avg clat = **26248 秒**、`>=2000ms 占 44%`。
- **不限速组同样 R=17.9/W=47.5、同样 44% 积压** → 去掉限速 R/W 比例不变，证明 R/W 不均衡是 fio 混合队列测量偏差（写走缓冲先排空），**非集群/网络特性**。
- 结论：randrw 只能看**合计吞吐**，R/W 分列不可解读为"读写能力"。**§8「新集群 R/W 不均衡待分析」为无效结论，关闭。**
- 与老集群"R=W=76.1 均衡"的差异同理是 fio 配置差异，非集群差异。

### 9.4 修正三：新集群不再做限速测试（策略决策）
- 限速测试唯一目的 = 与老集群千兆 JuiceFS 对比绝对值，本轮已完成（§4）。
- 新集群达标目标 = 不限速 100GbE 下有效带宽 ≥ 网卡 50%，只在不限速下有意义。
- **后续 JuiceFS 调优与 BeeGFS 基线均转不限速口径。** 详见 `doc/perf-analysis/`。
