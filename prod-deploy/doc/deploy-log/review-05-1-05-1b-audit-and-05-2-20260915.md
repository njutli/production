## 一、已达成的一致结论（8 条）

1. **05-1/05-1b 的 RUN 与数值有效**；4K/16K/64K/1M 的限制属于"对外精确单点披露"限制，
   ⛔ 不是数据无效。同 RUN 正反位置漂移 4K `8.8%`／16K `6.3%`／64K `2.3%` 仍过原 10% 规则，
   1M `11%` 已由原报告正确降级为 `RANGE_ONLY`。
2. **暂不新建全量 05-1c**；先取得竞品同口径 BS sweep 数据，只对两侧区间仍无法分辨的 BS
   做定点补测。
3. **256K 没有上传槽饱和的实测证据**，只有推算（见 §二.1）；须先过筛选门，
   **1M 才是 05-2 的主要因果验证点与唯一通过/不通过项**。
4. **1M 不再用单次 2×2**（无法抵抗时间漂移，见 §二.2），改为 `max-uploads` 单变量配对，
   按结果条件触发 buffer 配对。
5. **B4M Phase V 从 05-2 删除**；结论限定为 `NET_GAIN_UNPROVEN` + 已从交付候选撤出，
   ⛔ 既不写"有收益"也不写"无收益"。
6. **scrub 策略必须在 Gate 0 前二选一**，默认按 Phase 暂停 + 精确恢复（与 05-1b 一致）；
   ⛔ 禁止运行中改口径（指导书 §二.19.1）。
7. **主动 OSD compact 降为"恢复门连续超时后"的条件动作**，须预列精确命令、目标 OSD、
   次数预算并单独授权；默认恢复方式与 05-1/05-1b 一致（卷内 GC + 被动等 TiKV pending 归零）。
8. **竞品脚本补齐**双栏统计、实际时间锚、漂移裁决、资产清单、正式负载守卫、
   layout/正式测试分离，以及收尾容错。

## 二、复核过程中被修正的三处设计缺陷（均由证据推出）

### 2.1 256K 被误设为唯一通过项

原 05-2 把 256K 设为唯一通过/不通过项，隐含"256K 也已被证实受上传槽限制"。
但上传槽饱和的实测证据全部来自 1M/4M；05-1 Phase A 的 256K 格
`metrics-pre/post.prom` 为空（`METRICS_MISSING_ALLOWED_PHASE_A`）。
由现有数据可推算 256K 的在途水位：

```text
应用写 1749.3 MiB/s ÷ 0.25 MiB = 6997 PUT/s（B256+FUSE256K，bs 对齐，1 写 = 1 PUT）
× 同配置实测 PUT 平均延迟 15.03 -- 19.95 ms
⇒ Little 在途量 = 105 -- 140 / 150（70% -- 93%）
```

对比 1M/4M 实测在途量 `147.6 -- 149.8`、逐秒 gauge 全窗 `= 150.0`。
⇒ **256K 是"接近闸门"，1M/4M 是"顶在闸门"**。主变量验证改到 1M；
256K 先跑 1 格基线，过 `256K_UPLOAD_PROXIMITY_GATE`（`uploading` 正式窗 p95 >= 120，
沿用 05-1b §2.6 已预注册阈值）才进四格 C/T。
该阈值只表示"接近并发上限、值得测试"，⛔ 不得写成"已证明饱和"。

### 2.2 1M 的 2×2 只对 uploads 主效应免疫漂移

原设计 `P1→P2→P3→P4→P1'`（位置 1--5），设一阶漂移每位置 `−d`：

| 效应 | 两个估计的位置 | 偏置 | 是否抵消 |
|---|---|---|---|
| uploads 主效应 | `(P2−P1)` 2 vs 1；`(P3−P4)` 3 vs 4 | `−d` 与 `+d` | ✅ 一阶抵消 |
| buffer 主效应 | `(P4−P1)` 4 vs 1；`(P3−P2)` 3 vs 2 | `−3d` 与 `−d` | ❌ 同号不抵消 |
| 交互项 | 上两式之差 | 残留 | ❌ 不可分离 |

在已实测到位置漂移（05-1b S 组同配置 4K `39.6→24.5`，`−38.1%`）的环境里，
buffer 主效应与交互项与漂移共线。改为条件式两步，两个变量各自在平衡配对内估计，
⛔ 不再声称能估交互项（本任务的决策不需要交互项）。

### 2.3 机制门主次颠倒

原 `SCREEN_CONTINUE` 含 `OSD 写延迟恶化 < 10%`，等于让延迟否决吞吐候选：
既违反 Little 定律常识（并发↑必然排队↑），也违反指导书 §二.14
（验收门与有效性门不得共用阈值、带宽/CV/延迟不作删样门）。
先例 04-6b 的 seqwrite 机制门是"PUT 与 OSD `op_w` 完成率同步提高 >= 5%，
OSD 平均写延迟仅 `1.012×/1.020×`"——**完成率是主判据，延迟是旁证**。

最终采用的材料信号（GPT 建议进一步改用字节吞吐，避免受平均对象大小变化干扰）：

```text
1) READ 与 WRITE 相对两组位置对照的四个效应同向，较小效应 >= M = max(5%, 2ε)
2) 对象 PUT 字节吞吐（juicefs_object_request_data_bytes{method=PUT} 正式窗增量 / 窗长）
   与应用 WRITE 带宽同向材料提升；PUT ops/s 作辅助分解项
3) READ 方向无材料性回归
4) 在途量、PUT 平均延迟、OSD 延迟、秒级 CV、W4/W1 只用于说明收益成本与新瓶颈位置
若应用 WRITE 提升而对象 PUT 字节吞吐无对应变化 ⇒ 先判口径/采样证据不一致，
⛔ 不得直接宣称解闸成功
```

## 三、跨系统对比的裁决规则（新增预注册合同）

两侧都输出两栏：① fio 180 s summary；② `[15,175)` 正式窗 + W1--W4 + `W4/W1` + 秒级 CV。
竞品脚本保留 128 份 per-job 逐秒日志，因此**两栏对两栏都可算**，无需二选一。

```text
允许写方向性结论 = 两栏相对方向同号  AND  效应超过预注册的双方漂移/噪声范围
两栏异号             → STATISTIC_SENSITIVE，只报区间
两栏同号但未超过噪声 → INCONCLUSIVE，只报区间
两栏同号且超过噪声   → 才允许写领先/落后方向
```

噪声范围的预注册算法（保守取和）：

```text
μ_side(BS) = (位置1 + 位置2) / 2
ε_side(BS) = |位置1 − 位置2| / (2 × μ_side)
           = |位置1 − 位置2| / (位置1 + 位置2)    （相对半幅，各侧分别计算）
ε_pair(BS) = ε_ours(BS) + ε_theirs(BS)             （无量纲，保守取和）
判定        = |JuiceFS/竞品 − 1| > ε_pair(BS)
```

内部调优决策继续以正式窗为主口径（指导书 §二.13.4 不变）；summary 只作与公开 fio 命令
对齐的并列旁证。

## 四、范围约束（两项）

1. **本任务不扩展到 U450/U600。** 05-2 只回答 `U150→U300` 是否有材料收益；
   若 U300 有效则登记 L1 候选，是否继续提高并发另行决策。
   ⛔ 不在 05-2 预注册更高档位，避免退化成参数扫描。
2. **"双方状态协议"只冻结共同外部合同**（同 runtime／同 BS 矩阵／同 fio 负载／轮间不
   relayout／同名义 cooldown／两侧都报正反位置原始值与 `W1/W4`／测前申报资产与环境），
   ⛔ 不宣称两系统内部状态（元数据、GC、后端健康、恢复机制）等价。
   最终结论固定表述为：

   > 各自已部署环境下、相同 fio 命令与共同外部状态合同的端到端性能比较；
   > 不得归因为文件系统软件单因素。

## 五、议定的 05-2 执行规模与顺序

```text
1M  max-uploads 150/300     ：4 格，必做，唯一通过/不通过项
256K U150 基线（筛选格）     ：1 格，必做；⛔ 不进入任何效应量
256K U150/U300              ：4 格，仅 PROXIMITY_GATE 触发后执行
1M  buffer 300/1024         ：4 格，仅 U300 有材料收益且 buffer 成为新闸门后执行
临时卷 / layout / destroy   ：0 / 0 / 0
总格数                      ：最少 5 格，最多 13 格
预计环境时长                 ：约 1.5 -- 3 h
```

顺序约束：**256K 筛选格必须位于一次完整恢复门之后**，⛔ 不得紧接高强度 1M 写入，
以免累计状态压低 `uploading` 水位而产生假阴性；且该格与随后的 256K C/T 相邻，
保证门读数与效应量在同一状态区间。
