## 〇、背景

### 为什么是 K1 而不是原定的 K2

原 T1.1 是 K2（`rocksdb_cache_size` 512 MiB → 4 GiB，预期 3-8%，是 P1 期望最高项）。**2026-08-11 桌面核查把它否掉了**：

1. `BlueStore::_open_db` 调 `db->set_cache_size(cache_kv_ratio × cache_size)`（`BlueStore.cc:8262`），置 `set_cache_flag = true`；
2. `RocksDBStore.cc:554` 的 `if (!set_cache_flag) { cache_size = conf->rocksdb_cache_size; }` **分支永不进入** ⇒ 512 MiB 从未被读取；
3. 实际 KV(RocksDB) 缓存 = `bluestore_cache_size` 30 GiB × `kv_ratio` 0.30 = **~9 GiB**，是名义值的 18 倍 ⇒ "512 MiB 太小"这个前提本身不成立；
4. **即使能读到，block cache 也只在 `do_open` 里 `create_block_cache()` 建一次，改配置不 resize ⇒ 必须重启 OSD ⇒ 撞 F7**（重启本身 4.5-13% 噪声 > 效应 3-7%）。

第 4 条与 Ceph 版本无关，所以结案不需要 v17 源码复核。

⚑ **补充（2026-08-11 归属调查，见计划书 §5.6）**：这个选项**并非无用** —— 它是 **`ceph-mon` 的缓存比例阀**（`cache_kv_ratio = rocksdb_cache_size / mon_memory_target`，我们集群 512 MiB / 2 GiB = 0.25），在 mon 里**真生效且 runtime 可改**；在 BlueStore 里失效只是因为 BlueStore 接管了缓存预算。但 **mon 不在 JuiceFS 数据路径上** ⇒ 对七项基准效应结构性为 0 ⇒ parked → 04。

> **这条教训写进 `TUNING-SKILL.md`**：`runtime` flag + `ceph config set` 成功 + `ceph tell config get` 显示新值，**三个都满足仍可能完全不生效**。K1 已通过同一套核查（**B 路**：读路径内每 op 直读 `cct->_conf`，`BlueStore.cc:13129` / `:13547`），是真生效的。

### K1 的机制假设

`bluestore_default_buffered_read = true`（现值）时，BlueStore 读命中后会把数据也塞进 OSD 侧 page cache，形成**双缓冲**（BlueStore 自己的 `cache_data` + 内核 page cache）。关掉它可省一次拷贝、少一份内存压力。

**诚实的预期**：2-5%。而且有反向可能 —— 关掉后失去 page cache 兜底，某些访问模式可能变慢。**两个方向都是有效结果**，不要只期待正向。

**当前相关状态**（已实查，两臂共同条件，不改）：`bluestore_cache_size=30 GiB`、`kv_ratio=0.30`、`meta_ratio=0.05`、`autotune=false`；运行态 `cache_data` 仅 0.07 GiB / `cache_onode` 0.62 GiB / `cache_meta` 0.60 GiB。

**唯一通过/不通过项**：`|median(B臂) − median(A臂)|` 是否 ≥ 门槛。

## 五、通用注意事项（必带）

1. **统计口径**：验收口径是逐秒均值、窗口 `15 ≤ sec − t0 ≤ 175`（**全局 t0**，非每文件 t0 —— 后者有 1.3% 系统性偏差），取逐轮中位数。`rounds.tsv` 的 `BW_MiBs` 是 fio 汇总值，**不是验收口径**；本任务用它做过程记录与一致性核对是允许的，但口径要标明。
2. **冷态净化**：V4 每轮自带 `drop_caches`（3 节点）。🔴 注意 `drop_caches` 只清内核页缓存，**清不掉 BlueStore 进程内缓存** —— 这正是 H1 假设的由来，也正是 K1 这个旋钮的作用面。
3. **后端干净态**：读侧任务无写入，`compact_cooldown` 按 V4 默认行为即可。
4. **环境前置**：见步骤 1 七项。
5. **记录规范**：所有时刻标 **157 时间**（157 比 WSL 早 1 小时）。取数失败**不许回落成 0**，须重试并记录。
6. **取数纪律**：`ceph df` 必须 `--format=json` + `python3`（157 **无 `jq`**），`stored`/`max_avail` 全是**字节**（`/2**30`=GiB、`/2**40`=TiB）；`pgrep -c fio` 会匹配内核线程 `vfio-irqfd-clean`（恒 ≥1）⇒ 必须 `pgrep -af fio`。
7. **分层授权**：
   - ✅ **可自主**：写/调试 wrapper、重跑失败的单个 run、只读采集（`perf dump` / `dump_mempools` / `ceph df` / `ceph -s`）、`drop_caches`、`ceph tell osd.N compact`
   - ⚠ **须先报告再动**：任何偏离本任务书的操作、改 `ITEMS`/`RUNTIME`/`REPEAT`、动 V4 本体
   - ⛔ **绝对禁止**：见步骤 0 的 11 条
8. **skill 合规自查**：测试前（步骤 0）+ 测试后（步骤 5.4）各一次，结果写进报告。
