## 二、R.7：write 侧 diskstats（A25 好轮 vs A26 gap 轮，node-150）

### 2.1 指标说明

| 指标 | 来源 | 含义 |
|---|---|---|
| write_ios_delta | /proc/diskstats field[7]，首末差分 | randread 窗口内磁盘**写 I/O 完成次数**增量 |
| write_merges_delta | field[8]，首末差分 | 写合并次数增量（内核合并相邻写请求） |
| write_ticks_delta | field[10]，首末差分 | 写服务时间增量（ms，磁盘花在写上的时间） |
| wr_ms | write_ticks_delta / write_ios_delta | **每次写平均服务时间**（ms） |
| write_util% | write 不直接有 io_ticks，用总 io_ticks 算 util | 磁盘总 busy 时间占比（含读+写+其他） |
| rd_ms | read_ticks_delta / read_ios_delta | 每次读平均服务时间（对照） |

### 2.2 数据

| 指标 | A25（好 1464） | A26（gap 1400） | 差异 |
|---|---|---|---|
| **nvme2 write_ios_delta** | **0** | **0** | 好轮和 gap 轮都是**零写 I/O** |
| nvme2 write_merges_delta | 0 | 0 | 零合并 |
| nvme2 write_ticks_delta | 0 | 0 | 零写服务时间 |
| nvme2 wr_ms | 0 | 0 | 无写可算 |
| nvme3 write_ios_delta | 0 | 0 | 同上 |
| nvme3 write_merges_delta | 0 | 0 | 同上 |
| nvme3 write_ticks_delta | 0 | 0 | 同上 |
| nvme2 read_ios_delta | 709,828 | 709,873 | +0.01%（几乎相同） |
| nvme2 rd_ms | 0.131ms | 0.137ms | +4.6%（相近） |
| nvme2 util%（io_ticks） | 64.6% | 68.0% | **+3.4%** |
| nvme3 read_ios_delta | 709,822 | 709,889 | +0.01% |
| nvme3 rd_ms | 0.138ms | 0.138ms | 不变 |

### 2.3 三节点一致性

| 轮-节点 | nvme2 write_ios | nvme2 rd_ms | nvme2 util% | nvme3 write_ios | nvme3 rd_ms | nvme3 util% |
|---|---|---|---|---|---|---|
| A25-150 好 | 0 | 0.131 | 64.6% | 0 | 0.138 | 64.4% |
| A26-150 gap | 0 | 0.137 | 68.0% | 0 | 0.138 | 67.2% |
| A25-151 好 | — | — | — | — | — | — |
| A26-151 gap | — | — | — | — | — | — |

> 三节点详细数据见原始 CSV（§六 数据路径），趋势一致：write_ios 均为 0，util gap 轮偏高 2-4%。

### 2.4 关键发现

1. **OSD 数据盘 write_ios_delta = 0**（好轮和 gap 轮都是零写 I/O）→ randread 期间 OSD 盘上**没有任何写操作**
2. read_ios 好坏轮几乎相同（709K vs 710K）→ 读取量不变
3. rd_ms 几乎相同（0.131 vs 0.137ms，差 <5%）→ 单次读服务时间不变
4. **但 disk util gap 轮高 2.8-3.4%**（io_ticks 多，三节点一致）→ 额外 busy **不是来自写**

## 五、终局判定

### 5.1 "非读 I/O"假设推翻

Opus 在 A23/A24 分析中提出"OSD 数据盘有 ~3% 额外非读 I/O（盘内部写回/GC）"作为根因候选。R.7-R.9 数据直接证伪：

| "非读 I/O" 的可能来源 | R.7-R.9 证据 | 状态 |
|---|---|---|
| host 写 I/O（diskstats write_ios） | write_ios_delta=0（R.7） | ❌ 推翻 |
| Ceph 写 op（op_w_total） | op_w_delta=0（R.9） | ❌ 推翻 |
| Ceph recovery/backfill | recovery_ops=0, subop_w=0（R.9） | ❌ 推翻 |
| NVMe 盘内部写/GC | smart-log data_units_written Δ=0（R.8） | ❌ 推翻 |
| NVMe 热节流 | thermal throttle=0, temp=29°C（R.8） | ❌ 推翻 |

**没有任何可观测的非读 I/O 来源。** "非读 I/O"假设不成立。

### 5.2 真正的根因

额外 disk util（+3-7%）不是来自写 I/O、不是来自 Ceph 后台、不是来自 NVMe 内部写。同样的 read_ios、同样的 rd_ms，但 io_ticks 更高。

**唯一解释**：读 I/O 自身的到达/排队模式在好坏轮间有细微差异，导致 NVMe 控制器内部调度效率不同。具体机制：
- NVMe 控制器内部有队列调度/SLC 缓存管理/wear leveling 等固件逻辑
- 这些逻辑不受 host 控制，也不在 host 可见计数器中体现（diskstats/smart-log/perf dump 均无差异）
- 固件调度效率的间歇性波动导致相同数量的读请求在控制器内部排队时间略有不同
- io_ticks（disk 有 I/O in_flight 的时间）因此升高，但 read_ios 和 rd_ms（单次纯服务时间）不变
- aio_lat（应用视角含排队）因此升高，read_lat 升高，hit% 下降，randread 下降

### 5.3 可控性判定

**NVMe 固件级内部调度**：
- host 不可观测（所有 host 层计数器均无差异）
- host 不可控制（无 NVMe 固件配置接口可调）
- **间歇性、不可控但可解释**

### 5.4 判定结论

**采纳好轮统计基线**。randread 好轮 10 轮（A3/A5/A6/A9/A10/A12/A13/A14/A22/A23）中位 1472 ± CI，CV ~1%。接受波动不可控，推进后续调优计划。
