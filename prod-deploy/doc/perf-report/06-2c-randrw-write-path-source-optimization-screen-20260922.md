# 06-2c randrw写路径源码候选筛选报告

> 日期：2026-09-22  
> 有效RUN：`20260922-180504`  
> 裁决：`CORRECTNESS_PASS / SCREEN_STOP / RESOLUTION_INSUFFICIENT / PAIRED_EFFECTS_INCONCLUSIVE / NO_CANDIDATE / NOT_FOR_PRODUCTION`  
> 权威证据：`/mnt/c/SunRise/test/06-2c/20260922-180504/`

## 一、结论

06-2c验证了一个最小源码候选：对完整、对齐、非增长的256 KiB覆盖写提前冻结slice，仍沿用原有
`flushData → Finish → FIFO commitThread → meta.Write`链路，尝试把可提前完成的提交移出后续读前等待。
离线定向/race回归、真实FUSE已知内容smoke和四格排空后无缓存读回均通过；候选没有跳过数据上传、
元数据提交或正确性顺序。

性能筛选没有形成收益：T1/C1读写为`-5.59%/-5.60%`，T2/C2为`+2.49%/+2.51%`，两组方向相反；
同时C臂从C1到C2下降约`23.15%`，T臂从T1到T2下降约`16.5%`，使
`epsilon=23.149%`、材料线`M=46.298%`。描述性两轮均值中，T相对C读写均约`-2.08%`。

候选表现为**前段更快、后段更慢并留下更多暂存积压**，而不是提高完整180秒服务能力：两个配对中
T的首个45秒诊断窗均高于C，但末个45秒均低于C，排空还分别多`11s`和`17s`。本轮因此停止该候选，
不追加重跑或挑选漂亮样本，不升级为生产候选。这只关闭当前eager-freeze实现，不等于证明所有源码方向无空间。

## 六、最终决定

1. 06-2c完成，eager-freeze候选停止，不追加同模型样本或调参扫描。
2. T二进制及实验开关继续标记`NOT_FOR_PRODUCTION`，不得覆盖交付件或写成有效收益。
3. 本轮证明该实现最多重排突发时序，没有提高完整randrw平均带宽；继续围绕同一补丁微调的性价比低。
4. 其他源码方向如需研究，按07阶段单独立项，不反向改写06-2c裁决。
