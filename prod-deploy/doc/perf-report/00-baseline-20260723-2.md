### 1.2 本轮方法论变更

| 变更 | 旧方法（0723） | 新方法（本轮） | 目的 |
|------|---------------|---------------|------|
| 重建 | purge OSD + ceph orch（IDs 变） | destroy OSD + ceph-volume --osd-id（IDs 不变） | 保持 CRUSH 映射 |
| 轮间清理 | pool delete+recreate + OSD restart | soft-clean: juicefs destroy + compact + drop_caches（保留 pool、不重启 OSD） | 保持 pool_id 不变 |

### 1.3 测试流程

```
Stable-IDs 重建 → R1-A（fresh BlueStore）
  ↓ soft-clean（juicefs destroy + compact + drop_caches）
R1-A2
  ↓ soft-clean
R1-A3
  ↓ soft-clean
R1-A4
```

Group A = default readahead, REPEAT=3, randrw 变体 Y, bw_log 全采。

### 1.4 判定标准

- 轮内 CV<5%
- 组间 Δ<5%（R1-A vs R1-A2/A3/A4，soft-clean 后映射不变 → 应收敛）

## 五、结论

1. **soft-clean 对写类有效**：randwrite-true 全程 ±2% 收敛，layout A→A4 仅 -2.4%
2. **soft-clean 对读类有恢复效应但不完全**：randread A2 暴跌 -29% 后逐步恢复（A3 +7.5%, A4 +11.9%），A4 距 A 仍 -14.9%
3. **randread 恢复趋势加速**：A2→A3 +7.5%, A3→A4 +11.9%，外推 A5 可能接近 A
4. **mseqread 持续下降**：4062→3477→3449→2894，非 BlueStore 污染可解，可能另有根因
5. **randwrite-true 全程收敛**（±2%），说明 fresh volume 写不依赖 BlueStore 读路径状态

### 建议

- **继续 R1-A5**：randread 恢复趋势加速，A5 可能收敛到 A 的 5% 以内
- **mseqread 下降需单独排查**：可能是 tmpfs DB 的内存碎片化或 RocksDB block cache 竞争
