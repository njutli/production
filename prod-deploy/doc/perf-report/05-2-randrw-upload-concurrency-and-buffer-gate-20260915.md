## 一、结论

05-2 已完成并闭环，**不调整当前交付配置**：

1. 1 MiB randrw 下，`--max-uploads 150→300` 使上传在途量的 mean 由
   `149.81/149.94` 提高到 `193.87/177.45`（`+29.41%/+18.34%`），p95 由 `150/150`
   提高到 `300/286.45`，但两组配对带宽效应方向相反，READ 为
   `+4.32%/-4.64%`、WRITE 为 `+4.41%/-4.66%`；对象 PUT 吞吐也为
   `+1.62%/-5.88%`。未形成可复现的净收益。
2. PUT 平均延迟由对照臂的 `17.119/16.390 ms` 升至 U300 的
   `21.447/21.120 ms`（`+25.28%/+28.86%`）。四格 PUT 完成率的极差仅 `6.25%`：
   `max-uploads=150` 是对照臂会命中的**并发上限**，但不是当前的**吞吐上限**。
   新增并发主要转化为后端排队，而不是更高的对象完成率；停止继续扫描 U450/U600。
3. 由于同臂噪声 `ε=5.30%/5.36%` 超过 5%，Phase A 严格裁决为
   `RESOLUTION_INSUFFICIENT`，不能表述为“绝对无效”；但四条材料信号未通过，故不得登记
   `max-uploads=300` 候选。
4. 256 KiB 必做筛选格的 `uploading p95=98.15 < 120`，判定
   `GATE_NOT_TRIGGERED`；Phase B2 不执行。Phase C 的前置条件也未满足，已取消。

因此，本任务回答的是：**现有 1 MiB randrw 虽然触及 150 个上传槽，但单纯提高上传并发不能把
该算术闸门转化为稳定带宽收益，新的限制表现为对象后端完成率与排队时延；256 KiB 规格点在本次
正式窗内甚至未接近上传槽上限。**

### 3.2 配对效应与材料门

|---|---:|---:|---:|---:|

预注册的四条材料信号裁决如下：

| 材料信号 | 结果 | 依据 |
|---|---|---|
| READ/WRITE 两组效应同向且最小效应达到 M | FAIL | 两位置异号，且绝对值小于材料门 |
| PUT 字节吞吐同向材料提升 | FAIL | `+1.62%/-5.88%` |
| READ 无材料性回归 | PASS | 最差 `-4.64%`，未达到 `M=10.60%` |
| 应用 WRITE 与对象 PUT 口径自洽 | PASS | 每个位置内同号，但均未形成一致收益 |

综合裁决：`RESOLUTION_INSUFFICIENT / SCREEN_CONTINUE=FAIL`。这里的
`RESOLUTION_INSUFFICIENT` 表示本轮噪声不足以证明小效应为零；`SCREEN_CONTINUE=FAIL` 则表示
它没有达到继续投入正式矩阵或生产候选验证所需的证据门槛。

### 3.3 机制解释

U150 的 mean/p95/max 都接近或等于 150，证明对照臂确实命中并发上限。U300 后 mean
只升到 `193.87/177.45`，而不是长期维持在 p95 的 `300/286.45`；因此 p95 只表示峰值区间，
不能代表吞吐算术中的平均运行水位。

U300 使 mean 在途量增加 `29.41%/18.34%`，PUT 延迟增加 `25.28%/28.86%`，但 PUT 字节吞吐
只变化 `+1.62%/-5.88%`，四格 `put_ops/s` 仅在 `8564.84～9099.91`之间，极差 `6.25%`。这组数据证明：
`150` 个 slot 是可见的并发约束，但放宽后对象请求的完成率平台不动，新增在途量只放大排队。
因此它不是当前可通过继续加大并发来解锁的吞吐瓶颈；继续提高 U450/U600 没有证据依据。

### 3.4 统计口径稳健性与逐秒日志损失

以 fio summary 口径重算，结论不变：

| 指标 | 正式窗 bwlog | fio summary | 读法 |
|---|---:|---:|---|
| READ 同臂噪声 `ε` | 5.30% | 5.07% | 对应材料门 `M` 为 10.60% / 10.14% |
| WRITE 同臂噪声 `ε` | 5.36% | 5.05% | 对应材料门 `M` 为 10.73% / 10.10% |
| READ T1/C1、T2/C2 | `+4.32%/-4.64%` | `+3.45%/-4.87%` | 两种口径均异号且未过门 |
| WRITE T1/C1、T2/C2 | `+4.41%/-4.66%` | `+3.43%/-4.86%` | 两种口径均异号且未过门 |

逐秒 bwlog 全时段积分相对 fio `io_bytes` 存在小量亏损，且按执行位置单调收窄：READ
`-3.04%→-2.99%→-2.61%→-2.45%`，WRITE `-3.04%→-2.94%→-2.56%→-2.43%`。这说明逐秒日志对
绝对字节量有位置相关的轻微漏记，不宜将小效应解释为参数收益；但 summary 与正式窗的配对效应均
为异号，故 `RESOLUTION_INSUFFICIENT / SCREEN_CONTINUE=FAIL / NO_CANDIDATE` 不受口径切换影响。
