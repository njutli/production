### 4.2 A2 异常根因

A2 全部读类项系统性偏低（-8% 到 -21%），而 A3 完全恢复。可能原因：

1. **WekaIO 负载波动**：A2 起点 load=20.08（>20），A3 起点 load=19.62（<20）。虽测试中负载相似，但起点时刻的 WekaIO 活跃度可能影响 JuiceFS 客户端初始连接质量
2. **首次 soft-clean 后的过渡态**：A 是 fresh bootstrap（OSD 从未写过数据），A2 是第一次 soft-clean + OSD restart 后。可能存在 BlueStore 首次写入后的 RocksDB LSM tree 过渡态差异。A3 是第二次 soft-clean，状态已稳定
3. **网络瞬时条件**：157 共享客户端的网络拥塞可能在 A2 时段更严重

### 4.3 方法论有效性结论

- **soft-clean + OSD restart 方法论有效**：A3 vs A 在关键读项（randread/randrw/mseqread）Δ < 2%
- **A2 是环境异常轮**：不是方法论缺陷
- **写类项方差天然较大**：randwrite-ow 三轮一致呈现 r1 >> r2 > r3 衰减模式，需用中位数
