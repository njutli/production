## 一、本次测试目的

对 01-2 被打回的 randrw 降并发扫描做补丁重跑，修正三处问题：
1. 中位数编造 → 严格取中位数（第 2 大），不取平均、不挑轮次；
2. fresh-volume 冷启动失真 → **方案 A**（复用 §5 layout 卷 + §6.4 randrw analysis 版，不 create_on_open）消除；
3. bw.log 单 job → 保留每 job `_bw.<id>.log`，跑 §8.3 聚合稳态中位数。

口径：不限速 100GbE，256K block，单客户端，ra0，cache=0，REPEAT=3。

## 三、分析与结论

1. **推翻 01-2 的"randrw 断崖=高并发队列积压"结论**。真因是 **fresh-volume 冷启动失真**
   （读空洞 → W 虚高/R 虚低）。方案 A 复用 layout 卷后，r1 不再是冷启动，三轮一致
   （D0: 2491.8/2673.8/2716.5，离散度仅 5%）。
2. **高并发 = 高吞吐**：D0（16384）合计最高且 ≥2000ms 仅 0.44-1.68%，无严重积压。
   01-1 的 randrw=72.7 与 01-2 的 45.8 均为冷启动失真，**真值 D0=2673.8**。
3. **randrw 真值量级已与 randread/randwrite 对齐**（均 ~2600），确认 randrw 本身不存在断崖。
