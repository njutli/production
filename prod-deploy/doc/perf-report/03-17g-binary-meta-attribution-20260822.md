## 11. 分析方复算结果（opencode，2026-08-22）

**复算源**：`/home/lilingfeng/tmp/production/opencode-t3.17g.tar.gz`（md5 `cc05e9c0f268c11d88064bd1646b204e`，`md5sum -c` 通过）解包至本地 `/tmp/opencode/t17g/opencode-t3.17g/`；03-10 对照用本地存档 `/tmp/opencode/t310/opencode-fullbaseline-v4/`（4 个 randwrite cell 的原始 `jfs-stats-*` + `fio.txt`）。全部数值由 opencode 从原始计数器重算，未采用任何报告正文中的派生量（R21 §①）。

### 11.1 🔴 判决：F67 的二进制归因被推翻，且判为任务书 §八 情形④（口径不同）叠加情形②（归因不成立）

按 R21 §① 回查"0.91"的分子分母后发现：**03-10 的 0.91 与 03-17f 的 0.989 是两个不同的计数器**。在 03-10 的同一批 cell 里两者都存在且同时可算：

| 批次（口径） | `meta_ops_total_Write ÷ fuse_ops_total_write` | `transaction_..._seconds_total ÷ fuse_ops_total_write` |
|---|---|---|
| 03-10（旧 A-sync，4 轮） | **0.9100 / 0.9104 / 0.9109 / 0.9110**（均 0.9106） | 0.9544 / 0.9700 / 0.9687 / 0.9807（均 0.9684） |
| 03-17f（新 B-catchup，6 轮） | **0.9133 ~ 0.9141** | 0.9836 ~ 0.9914 |
| 03-17g O 臂（旧 A-sync，2 轮） | **0.9139 / 0.9144** | 0.9948 / 0.9943 |
| 03-17g N 臂（新 B-catchup，2 轮） | **0.9137 / 0.9138** | 0.9924 / 0.9948 |

⇒ **同口径比较：每写 meta 数 0.9106 → 0.9140，仅 +0.4%，等于没变**；F67 记载的"0.91 → 0.989 = +8.7%"全部由计数器错配产生。

⇒ 次级结论：`transaction/写op` 确实从 0.9684 涨到 0.984~0.995（**+2.5%**），是一个真实但小得多的变化，且**与二进制无关**（O 臂 0.9946 ≥ N 臂 0.9936）。它只能解释 −11% 里的约 2.5 pp。

**⛔ 因此 F67 必须整条撤回**，写侧 −11% 不得再表述为"B-catchup 二进制的确定代价"。

### 11.2 🔴 F44 模型的"逐 MiB 吻合"是恒等式，不构成验证

任务书 §十.3 要求的检验做完后发现该式无判别力：

```
meta率 ÷ (meta/写op) × 256KiB
  = (Δtxn/T) ÷ (Δtxn/Δwr) × 256KiB
  = (Δwr/T) × 256KiB            ← Δtxn 被完全约掉
  = fuse 写op率 × 256KiB ≡ fio 写带宽（bs 恒为 256K 时）
```

实测 17 个 randwrite cell（03-10 四 + 03-17f 六 + 03-17g 四 + NB8 三）**全部误差 ≤0.02%**，包括 BW 从 2572 到 3274 的全域。⇒ 03-17f 报告 §4.7 与 F67 里"模型预测 2684、实测均值 2684、逐 MiB 吻合"是代数恒等的必然结果，**零信息量**，不能作为 F67 的支撑证据（⇒ A39 第二条）。

### 11.3 🔴 二进制不是原因，且效应符号相反：新二进制写侧 **+5.8%**

| 臂 | 二进制 | 逐 cell BW (MiB/s) | 均值 | 臂内极差 |
|---|---|---|---|---|
| O（位置 1、4） | 旧 A-sync `1f60618c` | 2572 / 2603 | **2587.5** | 1.2% |
| N（位置 2、3） | 新 B-catchup `de93563f` | 2743 / 2733 | **2738.0** | 0.4% |

臂间差 **+5.82%**，是臂内极差的 5 倍；ABBA 布局（O·N·N·O）已抵消单调漂移 ⇒ **B-catchup 在写侧不是代价而是小幅收益**。

### 11.4 同日重锚：−11% 的全部来自 8 天环境漂移

| 比较 | 比值 |
|---|---|
| O 臂（今日，旧二进制 + msgr=3 + 256K = 03-10 完整口径） 2587.5 vs 03-10 均值 **3018.25** | **−14.27%** |
| N 臂（今日，新二进制 + msgr=3） 2738.0 vs 03-10 | −9.29% |
| 03-17f A 组（新二进制 + msgr=8） 2681 vs 03-10 | −11.17% |

⇒ 任务书 §八 预案里"若 O 臂 ≈2600 则是漂移而非二进制"的分支命中。**正确分解 = 环境漂移 −14.3%，二进制 +5.8%，二者相乘 0.857×1.058 = 0.907**，与 N 臂实测 −9.3% 一致；再叠加 msgr=8 的写侧中性（F65）即得 03-17f 的 −11.2%。

### 11.5 🔴 真因定位：meta `Write` 单 op 延迟 +35.6%，PUT 延迟反而下降

| 批次 | metaW/s | meta `Write` 延迟 | meta 在飞 | PUT 延迟 | PUT/写字节 | BW |
|---|---|---|---|---|---|---|
| 03-10（4 轮） | 10714~11157（均 10993.8） | **122.4~148.6 ms（均 138.10）** | 1367~1628（均 1517） | 7.36~7.75 ms（均 7.54） | 1.055~1.064 | 2941~3065 |
| 今日 O 臂（2 轮） | 9401 / 9519（均 9460.2） | **193.7 / 199.9 ms（均 196.82）** | 1845 / 1883 | 6.37 / 6.85 ms | 1.079 / 1.081 | 2572 / 2603 |
| 近两批 10 cell | 9401~10025 | **178.8~199.9 ms（均 187.32）** | 1747~1895 | 6.37~7.32 ms（均 6.79） | 1.071~1.081 | 2572~2743 |

三条同时成立：①每写 meta 数不变（11.1）；②meta 在飞并发**上升** 22.8%（1517 → 1863）；③meta 每 op 延迟**上升 35.6%**（138.1 → 187.3 ms，O 臂对 03-10 是 +42.5%）⇒ 客户端并未减压，是 meta 引擎每秒能提交的事务数下降，属**纯延迟受限**。同期 **PUT 延迟下降 10.1%**（7.54 → 6.79 ms）⇒ **⛔ 退化不在 Ceph 对象路径，在 TiKV meta 路径**。

跨 17 轮（三批次、两二进制、两 msgr 值）拟合 **`r(BW, 1/meta_Write_延迟) = 0.9151`**，延迟跨度 122.4~199.9 ms。⚑ 不是恒等式（在飞并发不恒定），但已足以把写侧带宽的一阶解释权交给 meta 延迟。

### 11.6 ⚑ 副产物：03-17f 的离群轮 NB8-r1 被解释，且证明 meta 引擎存在双态

03-17f 报告 §6 记录 Seg B `randwrite` r1=3274 为离群并剔除，当时未给原因。复算该 cell 三轮（**⚑ NB8 为 128K FUSE 口径，`meta/写op` 与 256K 不可比，但每 meta op 的延迟与速率可比**）：

| 轮 | BW | metaW/s | meta `Write` 延迟 |
|---|---|---|---|
| NB8-r1 | 3274 | 11916 | **136.62 ms** ← 03-10 快态 |
| NB8-r2 | 2639 | 9648 | 172.27 ms |
| NB8-r3 | 2659 | 9727 | 179.30 ms |

⇒ **同一挂载、同一配置、同一二进制内部发生了 136.6 → 172~179 ms 的状态跳变**，排除了二进制/配置/落位抽签的一切解释。**meta 引擎存在快态（≈137 ms）与慢态（≈180~200 ms）双态**，03-10 全 4 轮落在快态、近两批 10 cell 全落慢态。与 F44 的日/夜态属同族现象，但本例发生在同一挂载的连续三轮之内 ⇒ 切换粒度远小于"日/夜"。

### 11.8 结论与后续动作

1. **⛔ 撤回 F67**（写侧 −11% = 二进制变更）。归因错误由两处叠加造成：跨批比较了两个不同计数器（11.1）、并用一个恒等式当作交叉验证（11.2）。
2. **新增 F68**：写侧 −11% 的唯一定因 = meta `Write` 延迟由 138.1 ms 升至 187.3 ms（+35.6%），每写 meta 数不变、meta 在飞并发上升、PUT 延迟下降 ⇒ 退化在 TiKV meta 路径；`r(BW, 1/延迟) = 0.9151`（n=17）；且该延迟存在同挂载内跳变的双态（11.6）。
3. **新增 A39**：两条自我更正 —— ①引用历史报告派生量必须先回查分子分母（R21 §① 生效后次日即被自己触发，说明规则要落到复算脚本而非记忆）；②"模型与实测逐 MiB 吻合"在建立模型前必须先做代数约简，检查是否恒等。
4. **写侧三项基线解锁固化**（2707 / 1570 / 4676，见 03-17f §9.2），附注改为："系 meta 引擎慢态下的值；B-catchup 二进制自身在写侧为 +5.8%；快态下 randwrite 可达 3018 量级。"
5. **B1（TiKV 服务端逐 op 延迟）由"写侧四分支选择"升为唯一定因路径**，目标收窄为一个具体问题：meta `Write` 延迟为何从 138 ms 升至 187 ms，以及双态的触发条件。
6. **周报 §2.1 两行须改**：`randwrite −11.2% 来源 = 二进制变更`、`seqwrite −6.8% 来源 = 二进制变更` 均已被否证（后者未直测，但同源归因链已断，须降级为待查）。
