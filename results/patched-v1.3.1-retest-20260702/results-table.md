## 结论：patch 对各指标的影响

### 1. randread（随机读）— 确认提升
- 冷态 r1：33.6 → 37.2（+10.7%），原版波动仅 0.3%，**提升真实**
- 冷态 MAX：33.6 → 45.4（+35.1%），OSD cache 预热后改善更显著
- 与 loadRange bug 修复机制一致：减少不必要的全块读取，降低读放大

### 2. 顺序类指标 — 无显著变化
- seqread/seqwrite/multi-seqread/layout 变化均 <5%，在波动范围内
- multi-seqwrite -7.5%，可能是小幅波动，不足以判定退化

### 3. randwrite（随机写）— 表面下降但实为口径问题
- MAX 对比 53.5→45.2 看似下降 15.5%，但原版 53.5 是异常值（r1=29, r3=31.9 中的 r2=53.5）
- r1 对比 29.0→43.1 反而是提升，但原版 randwrite 波动太大，不结论

### 4. randrw（随机读写）— 波动内，不结论
- 原版跨轮波动 6.4→17.3（2.7 倍跨度），patched MAX=14.7 在原版区间内
- r1 对比 8.4→14.3 看似大幅提升，但原版 r1 本身不稳定（6.4 vs 10.4）

### 5. 原报告结论是否仍成立

| 原报告结论 | 是否仍成立 | 依据 |
|-----------|-----------|------|
| block-size 4M→256K 是核心突破 | ✓ 不受影响 | patch 不改 block-size |
| ra=0 救随机读、砸顺序读/randrw | ✓ 仍成立 | T2 vs T1: randread 53.4>37.2(救), seqread 51.6<78.8(砸), randrw 10.2<14.3(砸) |
| mu=150 是暖态 randrw 最优配置 | ✓ 仍成立 | T5 randrw 25.8 > T3 16.7 > T4 18.0 |
| randrw 是主要未达标瓶颈 | ✓ 仍成立 | 最优 randrw=25.8，距 59 差 2.3 倍 |
| 千兆网络是物理瓶颈 | ✓ 仍成立 | multi-seqread ~108-109 ≈ 千兆上限 |
| 暖态 randread >124 是缓存命中 | ✓ 仍成立 | T4 r2=118, r3=156 > 物理上限 |

**总结**：patch 修复了 loadRange bug，确认提升了随机读（r1 +10.7%, MAX +35.1%），对其他指标无显著影响，原报告所有结论仍然成立。
