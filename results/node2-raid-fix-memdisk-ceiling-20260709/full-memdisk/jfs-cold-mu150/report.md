## mu=150 vs 默认对比（multi-seqwrite）

| 配置 | multi-seqwrite | 说明 |

mu=150 在内存盘上效果更显著：后端无瓶颈时，上传管道成为唯一限制，mu=150 直接解除。

## 分析

### 写指标（验收核心）
- **seqwrite 117 MB/s = 2× 目标**：后端无磁盘瓶颈，JuiceFS 写打满 NIC
- **multi-seqwrite 69.8 MB/s**：mu=150 解除上传管道限制，从 49.4（默认mu）提升 41%
- **randwrite 126 MB/s = NIC 饱和**：direct I/O + 128j×128 并发直接打满
- **layout 104 MB/s**：128 job 并发写，接近 NIC（原 39.1 受后端磁盘限制）

### 读指标
- **seqread 106 MB/s**：接近 NIC（JuiceFS 顺序读开销小）
- **randread 54.1 MB/s**：3 轮极稳定（53.1/54.1/54.1），优于真盘 MAX 47.8（+13%）
  - 仍低于 rados bench 112 MB/s：JuiceFS 读路径开销（FUSE + TiKV 元数据 + object get）
  - 未过 59：冷态无 cache，每读需 TiKV lookup + object get 串行
- **randrw 48+48=96 MB/s 总**：读写各半，比真盘 19+19=38 翻 2.5 倍

### 全内存盘 vs 真盘的提升归因
- **写类大幅提升**（+60%~+166%）：消除 DATA 写路径瓶颈（RAID WriteThrough + SSD 争抢）
- **读类小幅提升**（+7%~+13%）：DATA 在 tmpfs 上读取更快，但 JuiceFS 读路径开销不变
- **稳定性大幅提升**：3 轮 stddev <1（真盘 r1-r3 波动 30-48），无 compaction/BlueFS stall 干扰

## 结论

1. **写验收指标 seqwrite 117 MB/s = 2× 目标** ✅
2. **全内存盘消除 DATA 写瓶颈后，所有写类指标大幅超越之前最优**
3. **mu=150 对 multi-seqwrite 关键**：内存盘上 +41%（上传管道成为唯一限制时 mu 最重要）
4. **randread 54.1 仍未过 59**：JuiceFS 读路径开销是独立瓶颈，与后端磁盘无关
5. **3 轮极稳定**：内存盘无 compaction/stall 干扰，数据可靠性高
